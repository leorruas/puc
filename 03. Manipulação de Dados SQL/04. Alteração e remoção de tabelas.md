# Alteração e remoção de tabelas

> **Contexto:** Este artigo apresenta os comandos DDL usados para modificar, remover, esvaziar e renomear tabelas. Os exemplos seguem principalmente a sintaxe do MySQL, utilizado nas aulas, e destacam diferenças importantes de portabilidade entre SGBDs.

Depois de criar uma tabela com `CREATE TABLE`, é comum precisar modificar sua definição, remover uma estrutura que deixou de ser necessária, apagar todos os registros mantendo a tabela ou simplesmente alterar seu nome. Para essas operações, SQL dispõe de comandos como `ALTER TABLE`, `DROP TABLE`, `TRUNCATE TABLE` e, em alguns SGBDs, `RENAME TABLE`.

Embora esses comandos costumem aparecer juntos em DDL, eles não fazem exatamente a mesma coisa. `ALTER TABLE` modifica a definição da tabela; `DROP TABLE` elimina a tabela inteira; `TRUNCATE TABLE` remove suas linhas, mas preserva sua estrutura; e `RENAME TABLE` altera seu nome.

## 1. Visão geral dos comandos

| Comando | O que faz | A tabela continua existindo? | Os dados continuam existindo? |
| --- | --- | --- | --- |
| `ALTER TABLE` | Modifica a estrutura da tabela | Sim | Em geral, sim |
| `DROP TABLE` | Remove a tabela do banco | Não | Não |
| `TRUNCATE TABLE` | Remove todas as linhas | Sim | Não |
| `RENAME TABLE` | Altera o nome da tabela | Sim | Sim |

A diferença central pode ser pensada assim: **ALTER reforma a tabela; DROP demole a tabela; TRUNCATE esvazia a tabela; RENAME troca a placa da porta**.

## 2. `ALTER TABLE`

`ALTER TABLE` modifica uma tabela que já existe. Dependendo do SGBD, ele pode adicionar ou remover colunas, alterar tipos de dados, criar ou remover restrições e realizar outras mudanças estruturais.

Considere a tabela criada anteriormente:

```sql
CREATE TABLE Fornecedor (
    Codigo CHAR(3) PRIMARY KEY,
    Nome CHAR(20)
);
```

### Adicionar uma coluna

Uma nova coluna pode ser adicionada com `ADD`. Em sintaxes compatíveis com o padrão SQL e também no MySQL, a palavra `COLUMN` pode aparecer de forma explícita para deixar a instrução mais legível.

Forma curta:

```sql
-- adiciona uma nova coluna à tabela Fornecedor
ALTER TABLE Fornecedor
ADD Email VARCHAR(100);
```

Forma explícita com `COLUMN`:

```sql
-- produz o mesmo efeito no MySQL
ALTER TABLE Fornecedor
ADD COLUMN Email VARCHAR(100);
```

As duas formas expressam a mesma ideia: alterar a tabela `Fornecedor` acrescentando a coluna `Email`, do tipo `VARCHAR(100)`.

Isso explica construções como a utilizada em questões da disciplina:

```sql
ALTER TABLE Livro
ADD numero_edicao NUMERIC NOT NULL;
```

Nesse exemplo, `numero_edicao` é a nova coluna, `NUMERIC` é seu tipo e `NOT NULL` determina que ela não aceite valores nulos. A ausência da palavra `COLUMN` não torna a instrução incorreta.

Para leitura, podemos decompor a sintaxe assim:

- `ALTER TABLE Fornecedor`: indica qual tabela será modificada;
- `ADD` ou `ADD COLUMN`: informa que uma nova coluna será acrescentada;
- `Email VARCHAR(100)`: define o nome e o tipo da coluna.

Depois da execução, a tabela passa a possuir `Codigo`, `Nome` e `Email`.

> **SQL padrão versus dialeto:** desde o início da disciplina, o foco é compreender a estrutura geral de SQL sem confundi-la com particularidades de um único SGBD. Por isso, os exemplos deste artigo mostram a forma conceitual do comando e, quando necessário, destacam extensões ou variantes específicas do MySQL.

### Alterar o tipo ou tamanho de uma coluna

No MySQL, `MODIFY COLUMN` pode alterar a definição de uma coluna existente:

```sql
-- aumenta o tamanho permitido para o nome
ALTER TABLE Fornecedor
MODIFY COLUMN Nome VARCHAR(100);
```

Aqui, `Nome` deixa de ser `CHAR(20)` e passa a ser `VARCHAR(100)`.

Essa sintaxe não é universal. SQL Server utiliza `ALTER COLUMN`, e PostgreSQL possui formas próprias de `ALTER COLUMN`. Por isso, é importante consultar o dialeto do SGBD utilizado.

### Renomear uma coluna

Em versões atuais do MySQL, uma coluna pode ser renomeada com:

```sql
-- altera apenas o nome da coluna
ALTER TABLE Fornecedor
RENAME COLUMN Nome TO RazaoSocial;
```

Depois da operação, os dados permanecem armazenados, mas a coluna passa a se chamar `RazaoSocial`.

### Remover uma coluna

Também podemos eliminar uma coluna:

```sql
-- remove a coluna Email e os valores armazenados nela
ALTER TABLE Fornecedor
DROP COLUMN Email;
```

Essa operação é destrutiva: ao remover a coluna, os dados que estavam nela também são perdidos.

## 3. `DROP TABLE`

`DROP TABLE` remove a tabela como objeto do banco de dados. Isso significa eliminar tanto sua estrutura quanto suas linhas.

```sql
-- remove completamente a tabela Fornecedor
DROP TABLE Fornecedor;
```

Depois da execução, `Fornecedor` deixa de existir no banco. Não é possível fazer um `SELECT` nela nem inserir novos dados porque a própria estrutura foi eliminada.

Quando queremos evitar erro caso a tabela já não exista, o MySQL permite:

```sql
-- remove a tabela apenas se ela existir
DROP TABLE IF EXISTS Fornecedor;
```

Essa forma é útil em scripts que podem ser executados mais de uma vez.

### Atenção a relacionamentos

Uma tabela pode ser referenciada por chaves estrangeiras de outras tabelas. Nesses casos, o SGBD pode impedir sua remoção para preservar a integridade referencial.

Portanto, `DROP TABLE` não deve ser entendido apenas como “apagar um arquivo”. Ele pode afetar a estrutura relacional do banco e precisa respeitar as dependências existentes.

## 4. `TRUNCATE TABLE`

`TRUNCATE TABLE` remove **todas as linhas** de uma tabela, mas mantém sua estrutura.

```sql
-- apaga todos os registros, mas mantém a tabela
TRUNCATE TABLE Fornecedor;
```

Depois da execução:

- a tabela `Fornecedor` continua existindo;
- suas colunas continuam definidas;
- a chave primária e demais estruturas continuam existindo;
- todas as linhas armazenadas são removidas.

Por isso, a frase “`TRUNCATE TABLE` altera a estrutura da tabela” seria imprecisa. O comando faz parte do conjunto de operações de definição/gerenciamento do objeto em muitos SGBDs, mas sua finalidade prática é **esvaziar a tabela preservando sua definição**.

### `TRUNCATE` não aceita `WHERE`

Não é possível escrever:

```sql
-- incorreto: TRUNCATE não remove apenas algumas linhas
TRUNCATE TABLE Fornecedor WHERE Codigo = '001';
```

`TRUNCATE` trabalha com a tabela inteira. Se o objetivo for remover apenas determinados registros, o comando apropriado será `DELETE`, que pertence à manipulação de dados.

## 5. `TRUNCATE TABLE` versus `DELETE`

Os dois comandos podem apagar dados, mas cumprem papéis diferentes.

| Aspecto | `TRUNCATE TABLE` | `DELETE` |
| --- | --- | --- |
| Remove todas as linhas | Sim | Sim, se usado sem `WHERE` |
| Permite escolher linhas com `WHERE` | Não | Sim |
| Mantém a tabela | Sim | Sim |
| Classificação usual | DDL | DML |
| Atua conceitualmente | Sobre a tabela inteira | Sobre linhas |

Exemplo de exclusão seletiva:

```sql
-- remove somente o fornecedor de código 001
DELETE FROM Fornecedor
WHERE Codigo = '001';
```

Exemplo de esvaziamento completo:

```sql
-- remove todas as linhas de uma vez
TRUNCATE TABLE Fornecedor;
```

No MySQL, `TRUNCATE TABLE` também reinicia o contador de uma coluna `AUTO_INCREMENT`. Esse comportamento é específico do SGBD e não deve ser generalizado automaticamente para todos os sistemas.

## 6. `RENAME TABLE`

No MySQL, `RENAME TABLE` altera o nome de uma tabela sem apagar seus dados.

```sql
-- renomeia a tabela Fornecedor para Fornecedores
RENAME TABLE Fornecedor TO Fornecedores;
```

Depois da execução, a tabela continua com suas colunas, restrições e registros, mas passa a ser acessada pelo novo nome:

```sql
SELECT *
FROM Fornecedores;
```

O MySQL também permite renomear uma tabela por meio de `ALTER TABLE`:

```sql
-- forma alternativa no MySQL
ALTER TABLE Fornecedor
RENAME TO Fornecedores;
```

### `RENAME TABLE` não é uma sintaxe universal

Esse é um ponto importante de portabilidade. O comando `RENAME TABLE` existe no MySQL, mas outros SGBDs adotam sintaxes diferentes.

Por exemplo, PostgreSQL utiliza:

```sql
ALTER TABLE Fornecedor
RENAME TO Fornecedores;
```

No SQL Server, renomeações tradicionalmente são feitas por mecanismos específicos como `sp_rename`. Portanto, ao trabalhar fora do MySQL, a documentação do SGBD deve ser consultada.

## 7. Script completo para executar do zero

O exemplo abaixo pode ser executado em **MySQL** do início ao fim. Ele cria o banco, seleciona o contexto, cria a tabela, insere alguns dados de teste e então aplica cada uma das operações estudadas.

> **Atenção:** o script termina com `TRUNCATE TABLE` e `DROP TABLE`. Portanto, os dados de teste e a tabela serão removidos ao final. Ele serve para prática e demonstração.

```sql
-- =========================================================
-- 1. CRIA E SELECIONA O BANCO DE DADOS
-- =========================================================

-- cria o banco somente se ele ainda não existir
CREATE DATABASE IF NOT EXISTS ComercioTI;

-- define ComercioTI como o banco atual da sessão
USE ComercioTI;


-- =========================================================
-- 2. PREPARA O EXEMPLO PARA PODER SER EXECUTADO NOVAMENTE
-- =========================================================

-- se uma execução anterior parou depois da renomeação,
-- remove a tabela com o nome novo
DROP TABLE IF EXISTS Fornecedores;

-- se uma execução anterior parou antes da renomeação,
-- remove a tabela com o nome original
DROP TABLE IF EXISTS Fornecedor;


-- =========================================================
-- 3. CRIA A TABELA INICIAL
-- =========================================================

CREATE TABLE Fornecedor (
    Codigo CHAR(3) PRIMARY KEY,
    Nome VARCHAR(100)
);


-- =========================================================
-- 4. INSERE DADOS DE TESTE
-- =========================================================

-- os INSERTs servem apenas para que possamos observar
-- o que acontece com os dados ao alterar, truncar e remover a tabela
INSERT INTO Fornecedor (Codigo, Nome)
VALUES ('001', 'Fornecedor Alfa');

INSERT INTO Fornecedor (Codigo, Nome)
VALUES ('002', 'Fornecedor Beta');

-- consulta os dados antes das alterações
SELECT *
FROM Fornecedor;


-- =========================================================
-- 5. ALTER TABLE: ADICIONA UMA COLUNA
-- =========================================================

ALTER TABLE Fornecedor
ADD COLUMN Email VARCHAR(100);

-- no MySQL, esta forma curta também seria válida:
-- ALTER TABLE Fornecedor ADD Email VARCHAR(100);

-- agora a tabela possui Codigo, Nome e Email
SHOW COLUMNS FROM Fornecedor;


-- =========================================================
-- 6. ALTER TABLE: ALTERA A DEFINIÇÃO DE UMA COLUNA
-- =========================================================

-- aumenta o limite de Nome de 100 para 150 caracteres
ALTER TABLE Fornecedor
MODIFY COLUMN Nome VARCHAR(150);

SHOW COLUMNS FROM Fornecedor;


-- =========================================================
-- 7. ALTER TABLE: RENOMEIA UMA COLUNA
-- =========================================================

ALTER TABLE Fornecedor
RENAME COLUMN Nome TO RazaoSocial;

-- os dados permanecem, mas a coluna mudou de nome
SELECT *
FROM Fornecedor;


-- =========================================================
-- 8. ALTER TABLE: REMOVE UMA COLUNA
-- =========================================================

-- remove a coluna Email e qualquer valor que estivesse nela
ALTER TABLE Fornecedor
DROP COLUMN Email;

SHOW COLUMNS FROM Fornecedor;


-- =========================================================
-- 9. RENAME TABLE: RENOMEIA A TABELA
-- =========================================================

RENAME TABLE Fornecedor TO Fornecedores;

-- a mesma tabela agora deve ser consultada pelo novo nome
SELECT *
FROM Fornecedores;


-- =========================================================
-- 10. TRUNCATE TABLE: REMOVE TODAS AS LINHAS
-- =========================================================

TRUNCATE TABLE Fornecedores;

-- a estrutura continua existindo, mas o resultado agora fica vazio
SELECT *
FROM Fornecedores;

-- podemos confirmar que as colunas continuam definidas
SHOW COLUMNS FROM Fornecedores;


-- =========================================================
-- 11. DROP TABLE: REMOVE A TABELA INTEIRA
-- =========================================================

DROP TABLE Fornecedores;

-- a partir daqui, a tabela não existe mais.
-- portanto, um SELECT * FROM Fornecedores geraria erro.
```

Esse script também ajuda a visualizar a diferença entre as operações. `ALTER TABLE` muda a definição sem necessariamente eliminar as linhas; `RENAME TABLE` preserva estrutura e dados, alterando apenas o nome; `TRUNCATE TABLE` mantém a estrutura e remove todo o conteúdo; e `DROP TABLE` elimina o próprio objeto.

Os comandos `INSERT`, `SELECT` e `SHOW COLUMNS` aparecem aqui apenas para tornar os efeitos visíveis durante a prática. `INSERT` e `SELECT` serão aprofundados nos conteúdos de manipulação e consulta de dados, enquanto `SHOW COLUMNS` é um comando específico do MySQL para inspecionar a estrutura da tabela.

## 8. Operações destrutivas exigem atenção

`DROP TABLE`, `TRUNCATE TABLE` e alguns usos de `ALTER TABLE` podem causar perda permanente de dados. Por isso, comandos DDL devem ser executados com atenção ao banco e à tabela selecionados.

Uma prática mental útil antes da execução é perguntar:

1. Estou no banco de dados correto?
2. Estou alterando a tabela correta?
3. Essa operação remove dados?
4. Existe alguma chave estrangeira ou dependência envolvida?
5. Eu realmente quero executar essa instrução agora?

Em ambiente real, essas perguntas também se conectam a permissões, backups, migrations e controle de versão do esquema.

## Pontos que costumam gerar confusão

- **`ADD` e `ADD COLUMN` podem representar a mesma adição de coluna.** No MySQL, `COLUMN` é opcional nesse contexto; exercícios baseados em SQL padrão podem apresentar a forma curta, como `ALTER TABLE Livro ADD numero_edicao NUMERIC NOT NULL`.
- **`ALTER TABLE` é um comando geral de modificação estrutural.** A ação específica vem depois, como `ADD`, `ADD COLUMN`, `MODIFY COLUMN` ou `DROP COLUMN`.
- **`DROP TABLE` remove dados e estrutura.** A tabela deixa de existir.
- **`TRUNCATE TABLE` remove os dados, mas mantém a estrutura.** Ele não é equivalente a `DROP TABLE`.
- **`TRUNCATE TABLE` não aceita `WHERE`.** Para excluir somente algumas linhas, utiliza-se `DELETE`.
- **`RENAME TABLE` é sintaxe do MySQL, não uma forma universal de SQL.** Outros SGBDs podem usar comandos diferentes.
- **`DROP COLUMN` também elimina os dados daquela coluna.** Alterar a estrutura pode provocar perda de informação.
- **DDL não significa apenas “criar coisas”.** Também inclui comandos de alteração e remoção de estruturas.
