# Comando `SELECT`

> **Contexto:** Este artigo introduz o comando `SELECT`, usado para recuperar dados armazenados em tabelas. O foco inicial está em quatro elementos fundamentais de uma consulta: `SELECT`, `FROM`, `WHERE` e `ORDER BY`. A partir deles, é possível escolher quais colunas serão apresentadas, indicar a origem dos dados, aplicar filtros e organizar as linhas retornadas.

Grande parte do uso cotidiano de um banco de dados consiste em **consultar informações já armazenadas**. Relatórios, tabelas, gráficos e respostas a perguntas de negócio normalmente dependem de consultas que recuperam e organizam dados existentes.

Uma consulta também é chamada de **query**. Em SQL, o principal comando usado para construir essas consultas é `SELECT`.

## 1. Consulta ou query

Uma query pode ser entendida como uma pergunta feita ao banco de dados.

Perguntas como:

- quais fornecedores estão cadastrados?
- qual é o código de determinado fornecedor?
- quais registros atendem a uma condição?
- em que ordem os resultados devem aparecer?

podem ser traduzidas para consultas SQL.

O banco não altera os dados apenas porque eles foram consultados. `SELECT` é utilizado para **recuperar e apresentar informações**.

## 2. Estrutura básica de uma consulta

Nesta etapa da disciplina, uma consulta pode ser pensada a partir de quatro partes:

```sql
SELECT colunas
FROM tabela
WHERE condição
ORDER BY coluna;
```

Cada cláusula responde a uma pergunta diferente:

| Parte | Pergunta que responde |
| --- | --- |
| `SELECT` | Quais colunas quero apresentar? |
| `FROM` | De qual tabela vêm os dados? |
| `WHERE` | Quais linhas devem ser consideradas? |
| `ORDER BY` | Como as linhas retornadas devem ser organizadas? |

Nem toda consulta precisa necessariamente usar todas essas partes. `SELECT` e `FROM` já permitem consultas simples; `WHERE` e `ORDER BY` acrescentam filtragem e ordenação.

## 3. `SELECT`: escolher as colunas

`SELECT` indica quais colunas serão apresentadas no resultado da consulta.

Considere a tabela:

```text
Fornecedor
-------------------------
Codigo | Nome
-------------------------
001    | Fornecedor 1
002    | Fornecedor 2
003    | Fornecedor 3
```

Se quisermos visualizar apenas os nomes:

```sql
SELECT Nome
FROM Fornecedor;
```

O resultado contém apenas a coluna solicitada:

| Nome |
| --- |
| Fornecedor 1 |
| Fornecedor 2 |
| Fornecedor 3 |

Também podemos solicitar mais de uma coluna:

```sql
SELECT Codigo, Nome
FROM Fornecedor;
```

Nesse caso, o resultado apresenta `Codigo` e `Nome`.

## 4. O asterisco `*`

Nos exemplos anteriores da disciplina, `SELECT *` foi utilizado para conferir o conteúdo de uma tabela:

```sql
SELECT *
FROM Fornecedor;
```

O asterisco indica que queremos recuperar **todas as colunas** disponíveis no resultado dessa consulta.

Por isso:

```sql
SELECT *
FROM Fornecedor;
```

pode ser lido como:

> selecione todas as colunas da tabela `Fornecedor`.

Para consultas de estudo e inspeção, essa forma é prática. Quando queremos deixar explícitas apenas as informações necessárias, podemos listar as colunas pelo nome.

## 5. `FROM`: indicar a origem dos dados

`FROM` identifica a tabela de onde os dados serão recuperados.

Em:

```sql
SELECT Codigo, Nome
FROM Fornecedor;
```

`Fornecedor` é a origem dos dados da consulta.

A leitura completa é:

> selecione as colunas `Codigo` e `Nome` da tabela `Fornecedor`.

Esse modo de leitura ajuda a aproximar a sintaxe SQL de uma pergunta em linguagem natural.

## 6. `WHERE`: filtrar as linhas

`WHERE` apresenta uma condição que restringe quais linhas serão retornadas.

Por exemplo:

```sql
SELECT Codigo, Nome
FROM Fornecedor
WHERE Codigo = '002';
```

A consulta pede:

> selecione `Codigo` e `Nome` da tabela `Fornecedor` onde `Codigo` seja igual a `'002'`.

Se a tabela contiver vários fornecedores, apenas as linhas que satisfizerem a condição aparecerão no resultado.

### A mesma cláusula em contextos diferentes

`WHERE` já apareceu no [[05. Comandos INSERT, UPDATE e DELETE|artigo 05]] com `UPDATE` e `DELETE`.

O princípio é o mesmo: **`WHERE` restringe quais linhas satisfazem uma condição**.

A diferença está no que o comando faz com essas linhas:

| Comando | Papel de `WHERE` |
| --- | --- |
| `SELECT` | determina quais linhas serão retornadas |
| `UPDATE` | determina quais linhas serão alteradas |
| `DELETE` | determina quais linhas serão removidas |

Portanto, aprender `WHERE` não serve apenas para consultas. A mesma ideia de filtragem reaparece em diferentes comandos SQL. Os operadores e predicados usados para construir filtros mais ricos — como `<>`, `>=`, `AND`, `OR`, `BETWEEN`, `IN`, `IS NULL` e `LIKE` — são aprofundados em [[07. Operadores e condições em consultas SQL|07. Operadores e condições em consultas SQL]].

## 7. `ORDER BY`: ordenar o resultado

`ORDER BY` classifica as linhas retornadas pela consulta segundo uma coluna.

Por exemplo:

```sql
SELECT Codigo, Nome
FROM Fornecedor
ORDER BY Nome;
```

A consulta recupera `Codigo` e `Nome` e organiza o resultado com base na coluna `Nome`.

É importante perceber que `ORDER BY` atua sobre a **apresentação do resultado da consulta**. Ele não reorganiza fisicamente a estrutura da tabela.

## 8. Combinando `SELECT`, `FROM`, `WHERE` e `ORDER BY`

As quatro partes podem aparecer juntas:

```sql
SELECT Codigo, Nome
FROM Fornecedor
WHERE Codigo = '002'
ORDER BY Nome;
```

Podemos decompor a instrução assim:

- `SELECT Codigo, Nome`: apresentar essas colunas;
- `FROM Fornecedor`: buscar os dados nessa tabela;
- `WHERE Codigo = '002'`: manter apenas as linhas que satisfazem a condição;
- `ORDER BY Nome`: organizar o resultado pela coluna `Nome`.

O modelo mental é:

> **o que mostrar → de onde buscar → quais linhas considerar → como organizar o resultado**.

## 9. `SELECT` não altera os dados

Uma consulta com `SELECT` recupera informações para leitura.

Por exemplo:

```sql
SELECT *
FROM Fornecedor;
```

não adiciona, modifica nem remove linhas. Ele apenas solicita ao SGBD que produza um resultado a partir dos dados já existentes.

Essa distinção ajuda a separar os comandos estudados até aqui:

| Objetivo | Comando |
| --- | --- |
| Criar estrutura | `CREATE TABLE` |
| Alterar estrutura | `ALTER TABLE` |
| Inserir linhas | `INSERT` |
| Alterar valores | `UPDATE` |
| Excluir linhas | `DELETE` |
| Consultar dados | `SELECT` |

## 10. Do dado armazenado à informação

O valor de `SELECT` não está apenas em “mostrar uma tabela”. Consultas permitem transformar dados armazenados em respostas úteis.

Uma mesma tabela pode responder perguntas diferentes dependendo das colunas escolhidas, dos filtros aplicados e da forma de ordenar o resultado.

Por exemplo:

```sql
-- todos os dados
SELECT *
FROM Fornecedor;
```

```sql
-- apenas os nomes
SELECT Nome
FROM Fornecedor;
```

```sql
-- apenas o fornecedor de código 002
SELECT Codigo, Nome
FROM Fornecedor
WHERE Codigo = '002';
```

```sql
-- todos os fornecedores, organizados pelo nome
SELECT Codigo, Nome
FROM Fornecedor
ORDER BY Nome;
```

A tabela continua sendo a mesma. O que muda é a **pergunta formulada pela consulta**.

## 11. Script de prática

O exemplo abaixo prepara alguns dados e executa consultas simples:

```sql
USE ComercioTI;

DROP TABLE IF EXISTS Fornecedor;

CREATE TABLE Fornecedor (
    Codigo CHAR(3) PRIMARY KEY,
    Nome VARCHAR(100)
);

INSERT INTO Fornecedor (Codigo, Nome)
VALUES
    ('001', 'Fornecedor Alfa'),
    ('002', 'Fornecedor Beta'),
    ('003', 'Fornecedor Gama');


-- =========================================================
-- 1. TODAS AS COLUNAS
-- =========================================================

SELECT *
FROM Fornecedor;


-- =========================================================
-- 2. APENAS UMA COLUNA
-- =========================================================

SELECT Nome
FROM Fornecedor;


-- =========================================================
-- 3. COLUNAS ESPECÍFICAS
-- =========================================================

SELECT Codigo, Nome
FROM Fornecedor;


-- =========================================================
-- 4. FILTRO COM WHERE
-- =========================================================

SELECT Codigo, Nome
FROM Fornecedor
WHERE Codigo = '002';


-- =========================================================
-- 5. ORDENAÇÃO DO RESULTADO
-- =========================================================

SELECT Codigo, Nome
FROM Fornecedor
ORDER BY Nome;


-- =========================================================
-- 6. FILTRO E ORDENAÇÃO JUNTOS
-- =========================================================

SELECT Codigo, Nome
FROM Fornecedor
WHERE Codigo = '002'
ORDER BY Nome;
```

## Pontos que costumam gerar confusão

- **`SELECT` escolhe quais colunas aparecem no resultado.** Ele não modifica a estrutura da tabela.
- **`FROM` indica a origem dos dados.** Nesta etapa, a origem apresentada é uma tabela.
- **`WHERE` filtra linhas.** Em `SELECT`, define quais linhas serão retornadas; em `UPDATE` e `DELETE`, delimita quais linhas serão alteradas ou removidas.
- **`ORDER BY` ordena o resultado da consulta.** Ele não reorganiza fisicamente a tabela.
- **`SELECT *` significa selecionar todas as colunas.** O asterisco não significa “todas as linhas”; a quantidade de linhas depende da consulta e de possíveis filtros.
- **Uma query é uma consulta.** O resultado pode alimentar relatórios, tabelas, gráficos e outras formas de análise.
- **A mesma tabela pode responder perguntas diferentes.** Mudar colunas, filtros e ordenação muda o resultado da consulta, não necessariamente os dados armazenados.
