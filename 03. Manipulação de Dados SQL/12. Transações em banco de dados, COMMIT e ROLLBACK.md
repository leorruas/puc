# Transações em banco de dados, `COMMIT` e `ROLLBACK`

> **Contexto:** Este artigo introduz transações como unidades lógicas de trabalho em bancos de dados, especialmente em ambientes multiusuário. O foco está em agrupar várias operações SQL em um único bloco coerente, efetivá-las com `COMMIT` ou desfazê-las com `ROLLBACK` e compreender a ideia de atomicidade por meio do exemplo clássico de transferência entre contas.

Em sistemas reais, várias pessoas e aplicações podem acessar o mesmo banco ao mesmo tempo. Uma aplicação pode atualizar estoque, outra registrar uma venda, outra reservar uma viagem e outra transferir dinheiro entre contas. O SGBD precisa coordenar essas leituras e escritas de forma confiável, e as **transações** são uma das estruturas centrais para isso.

## Transação, unidade lógica e atomicidade

Uma transação é uma **unidade lógica de trabalho** formada por uma ou mais operações relacionadas entre si. Essas operações podem envolver inserção, exclusão, atualização ou recuperação de dados, mas o ponto principal é que o conjunto represente uma única ação coerente do ponto de vista do negócio.

Uma transferência de R$ 100 entre duas contas mostra bem essa ideia: é necessário retirar R$ 100 da conta de origem e acrescentar R$ 100 à conta de destino. Se apenas o débito acontecer e o crédito falhar, a transferência não foi concluída corretamente. As duas alterações pertencem, portanto, à mesma unidade lógica.

A indivisibilidade dessa unidade corresponde à **atomicidade**:

> **Ou todas as operações da transação são efetivadas, ou nenhuma delas deve permanecer efetivada.**

Se uma falha ocorrer entre o débito e o crédito — por erro em uma instrução, falha no servidor, queda de energia, problema de disco ou outra interrupção — as alterações parciais precisam ser desfeitas. Isso evita um estado incoerente como:

```text
Conta A: -100
Conta B: +0
```

quando o resultado esperado era:

```text
Conta A: -100
Conta B: +100
```

Uma transação pode conter apenas uma instrução, mas seu valor fica mais evidente quando várias instruções precisam funcionar juntas. Uma atualização isolada:

```sql
UPDATE Conta
SET Saldo = Saldo - 100
WHERE Numero = 123;
```

é diferente de uma unidade lógica completa:

```sql
BEGIN TRANSACTION;

UPDATE Conta
SET Saldo = Saldo - 100
WHERE Numero = 123;

UPDATE Conta
SET Saldo = Saldo + 100
WHERE Numero = 456;

COMMIT;
```

No segundo caso, as duas atualizações representam uma única ação de negócio.

## Ciclo da transação: iniciar, confirmar ou desfazer

Uma transação possui três momentos conceituais: **início**, **execução das operações** e **encerramento**. O encerramento pode confirmar ou cancelar o que foi feito.

No SQL Server, a abertura explícita pode ser feita com:

```sql
BEGIN TRANSACTION;
```

No MySQL, a forma utilizada é:

```sql
START TRANSACTION;
```

O conceito é o mesmo, mas a sintaxe de início varia entre os dialetos.

Depois de executar as instruções da unidade de trabalho, existem dois caminhos principais:

| Comando | Função |
| --- | --- |
| `COMMIT` | confirma as alterações e encerra a transação com sucesso |
| `ROLLBACK` | desfaz as alterações ainda não confirmadas e encerra a transação |

Por exemplo, uma inserção confirmada:

```sql
BEGIN TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

COMMIT;
```

faz com que a inclusão seja efetivada. Já:

```sql
BEGIN TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

ROLLBACK;
```

desfaz a inclusão antes da confirmação.

O mesmo princípio vale para exclusões:

```sql
BEGIN TRANSACTION;

DELETE FROM Produto
WHERE Codigo = 100;

ROLLBACK;
```

A linha pode desaparecer durante a transação, mas a exclusão é desfeita pelo `ROLLBACK`. Se a intenção for confirmá-la:

```sql
BEGIN TRANSACTION;

DELETE FROM Produto
WHERE Codigo = 100;

COMMIT;
```

Isso se conecta diretamente ao cuidado com `DELETE` discutido em [[05. Comandos INSERT, UPDATE e DELETE#10. O perigo de `DELETE` sem `WHERE`|INSERT, UPDATE e DELETE]].

## Aplicando transações a operações de negócio

A utilidade de uma transação aparece quando várias instruções representam uma única ação que não pode ficar incompleta.

Na transferência bancária:

```sql
BEGIN TRANSACTION;

UPDATE Conta
SET Saldo = Saldo - 100
WHERE Numero = 123;

UPDATE Conta
SET Saldo = Saldo + 100
WHERE Numero = 456;

COMMIT;
```

a intenção é que as duas atualizações sejam confirmadas juntas. Se algum erro impedir a segunda operação, a transação deve seguir o caminho de desfazer as alterações:

```sql
ROLLBACK;
```

A mesma lógica pode ser aplicada a outras situações, como registrar uma venda e atualizar estoque, inserir dados relacionados em mais de uma tabela ou cancelar alterações experimentais antes de confirmá-las.

Uma forma útil de raciocinar é:

1. iniciar a transação;
2. executar as operações relacionadas;
3. verificar se todas puderam ser concluídas;
4. usar `COMMIT` se tudo deu certo;
5. usar `ROLLBACK` se a unidade de trabalho precisar ser desfeita.

## Ambiente multiusuário e gerenciador de transações

Em um ambiente multiusuário, diferentes aplicações podem executar operações de leitura e escrita simultaneamente sobre os mesmos bancos de dados. O SGBD precisa coordenar essas unidades de trabalho para preservar a confiabilidade dos dados.

O **gerenciador de transações** é o componente responsável por administrar essas operações e seus efeitos sobre os dados. A aplicação envia comandos ao SGBD, mas é o sistema gerenciador que controla a execução transacional, incluindo a confirmação ou o desfazimento das alterações.

A atomicidade é uma parte desse problema: ela impede que uma unidade de trabalho fique parcialmente concluída. O nome **ACID** abrange outras propriedades além da atomicidade, mas elas não são desenvolvidas neste artigo.

## Script de prática

### SQL Server

```sql
-- testa uma inserção e desfaz
BEGIN TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

SELECT *
FROM Produto
WHERE Codigo = 100;

ROLLBACK;


-- executa a mesma inserção e confirma
BEGIN TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

COMMIT;


-- testa uma exclusão e desfaz
BEGIN TRANSACTION;

DELETE FROM Produto
WHERE Codigo = 100;

ROLLBACK;


-- executa a exclusão e confirma
BEGIN TRANSACTION;

DELETE FROM Produto
WHERE Codigo = 100;

COMMIT;
```

### MySQL

```sql
START TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

ROLLBACK;


START TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

COMMIT;
```

## Pontos que costumam gerar confusão

- **Uma transação é uma unidade lógica de trabalho, não apenas um comando SQL.** Ela pode reunir várias instruções que precisam funcionar como uma única ação.
- **`COMMIT` e `ROLLBACK` encerram a transação de maneiras diferentes.** `COMMIT` confirma; `ROLLBACK` desfaz.
- **Uma alteração pode aparecer antes do `COMMIT` e ainda assim ser desfeita.** Enquanto a transação não tiver sido confirmada, `ROLLBACK` pode cancelar suas alterações.
- **`ROLLBACK` pode desfazer inserções, exclusões e outras alterações da transação.**
- **Atomicidade significa tudo ou nada.** Uma operação composta, como transferência bancária, não deve permanecer parcialmente concluída.
- **SQL Server e MySQL não usam exatamente a mesma sintaxe para iniciar a transação.** Os exemplos usam `BEGIN TRANSACTION` no SQL Server e `START TRANSACTION` no MySQL.
- **ACID é mais amplo do que atomicidade.** Neste ponto, apenas a indivisibilidade da transação foi desenvolvida.
