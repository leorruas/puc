# Transações em banco de dados, `COMMIT` e `ROLLBACK`

> **Contexto:** Este artigo introduz transações como unidades lógicas de trabalho em bancos de dados, especialmente em ambientes multiusuário. O foco está em agrupar várias operações SQL em um único bloco coerente, efetivá-las com `COMMIT` ou desfazê-las com `ROLLBACK`, além de compreender a ideia de atomicidade por meio do exemplo clássico de transferência entre contas.

Em sistemas reais, várias pessoas e aplicações podem acessar o mesmo banco ao mesmo tempo. Uma aplicação pode atualizar estoque, outra registrar uma venda, outra reservar uma viagem e outra transferir dinheiro entre contas. O SGBD precisa coordenar essas leituras e escritas de forma confiável.

É nesse contexto que entram as **transações**.

## 1. O que é uma transação

Uma transação é uma **unidade lógica de trabalho** formada por uma ou mais operações relacionadas entre si. Essas operações podem envolver inserção, exclusão, atualização ou recuperação de dados.

O importante é que o conjunto faça sentido como uma única ação do ponto de vista do negócio.

## 2. Uma transação representa uma ação completa do negócio

Considere uma transferência de R$ 100 entre duas contas. A operação exige pelo menos duas etapas:

1. retirar R$ 100 da conta de origem;
2. acrescentar R$ 100 à conta de destino.

Essas duas alterações pertencem à mesma unidade lógica. Se apenas o débito acontecer e o crédito falhar, não existe uma transferência concluída corretamente.

## 3. Atomicidade: tudo ou nada

A indivisibilidade da transação corresponde à ideia de **atomicidade**.

> **Ou todas as operações da transação são efetivadas, ou nenhuma delas deve permanecer efetivada.**

Se uma falha ocorrer depois do débito e antes do crédito, as alterações já realizadas precisam ser desfeitas.

Isso evita um estado como:

```text
Conta A: -100
Conta B: +0
```

quando o objetivo era:

```text
Conta A: -100
Conta B: +100
```

## 4. Falhas podem acontecer entre operações

Uma transação pode ser interrompida por falha no servidor, queda de energia, falha no disco, erro em uma instrução ou outra condição que impeça a conclusão da unidade de trabalho.

Se a transação não puder terminar corretamente, as alterações parciais não devem permanecer como se a operação tivesse sido concluída.

## 5. Delimitando uma transação

No SQL Server, a forma usada para iniciar explicitamente uma transação é:

```sql
BEGIN TRANSACTION;
```

Depois vêm as instruções que pertencem à unidade de trabalho. Ao final, existem dois caminhos principais:

```sql
COMMIT;
```

ou:

```sql
ROLLBACK;
```

`COMMIT` encerra a transação **efetivando** suas alterações. `ROLLBACK` encerra a transação **desfazendo** as alterações ainda não confirmadas.

## 6. `COMMIT`: confirmar a transação

```sql
BEGIN TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

COMMIT;
```

Depois do `COMMIT`, a inserção fica efetivada.

> **`COMMIT` = confirmar e encerrar com sucesso.**

## 7. `ROLLBACK`: desfazer a transação

```sql
BEGIN TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

ROLLBACK;
```

A linha pode ser consultada durante a transação, mas o `ROLLBACK` desfaz a inclusão antes que ela seja confirmada.

> **`ROLLBACK` = cancelar as alterações da transação e retornar ao estado anterior.**

## 8. `ROLLBACK` também pode desfazer um `DELETE`

```sql
BEGIN TRANSACTION;

DELETE FROM Produto
WHERE Codigo = 100;

ROLLBACK;
```

A linha foi removida durante a transação, mas a exclusão é desfeita pelo `ROLLBACK`.

Se a intenção for tornar a exclusão definitiva:

```sql
BEGIN TRANSACTION;

DELETE FROM Produto
WHERE Codigo = 100;

COMMIT;
```

Isso se conecta diretamente ao cuidado com `DELETE` discutido em [[05. Comandos INSERT, UPDATE e DELETE#10. O perigo de `DELETE` sem `WHERE`|INSERT, UPDATE e DELETE]].

## 9. Exemplo de transferência bancária

Uma transferência pode ser representada de forma simplificada assim:

```sql
BEGIN TRANSACTION;

UPDATE Conta
SET Saldo = Saldo - 100
WHERE Numero = 123;

UPDATE Conta
SET Saldo = Saldo + 100
WHERE Numero = 456;

COMMIT;
```

A intenção é que as duas atualizações formem uma única operação lógica. Se algum erro impedir a segunda atualização, a transação deve ser desfeita com:

```sql
ROLLBACK;
```

Assim, o débito não permanece isoladamente.

## 10. SQL Server e MySQL usam formas diferentes para iniciar

No SQL Server:

```sql
BEGIN TRANSACTION;
```

No MySQL:

```sql
START TRANSACTION;
```

Depois disso, os comandos de encerramento permanecem `COMMIT` ou `ROLLBACK`.

O conceito é o mesmo; a sintaxe de início varia entre os dialetos.

## 11. Exemplo equivalente no MySQL

```sql
START TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

COMMIT;
```

Para testar a mesma operação sem mantê-la:

```sql
START TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

ROLLBACK;
```

## 12. O gerenciador de transações

Em um ambiente multiusuário, o SGBD precisa coordenar diferentes operações de leitura e escrita que acontecem simultaneamente.

O **gerenciador de transações** é o componente responsável por administrar essas unidades de trabalho e seus efeitos sobre os dados.

Uma aplicação normalmente não trabalha isolada: vários usuários podem executar operações ao mesmo tempo sobre os mesmos recursos.

## 13. Transação não é a mesma coisa que um único comando

Uma transação pode conter apenas uma instrução, mas seu valor fica mais evidente quando várias instruções precisam funcionar juntas.

Compare uma atualização isolada:

```sql
UPDATE Conta
SET Saldo = Saldo - 100
WHERE Numero = 123;
```

com uma unidade lógica completa:

```sql
BEGIN TRANSACTION;

UPDATE Conta
SET Saldo = Saldo - 100
WHERE Numero = 123;

UPDATE Conta
SET Saldo = Saldo + 100
WHERE Numero = 456;

COMMIT;
```

No segundo caso, as duas atualizações representam uma única ação de negócio.

## 14. Fluxo mental de uma transação

Uma forma útil de raciocinar é:

1. iniciar a transação;
2. executar as operações relacionadas;
3. verificar se todas puderam ser concluídas;
4. usar `COMMIT` se tudo deu certo;
5. usar `ROLLBACK` se a unidade de trabalho precisar ser desfeita.

## 15. Script de prática

### SQL Server

```sql
-- testa uma inserção e desfaz
BEGIN TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

SELECT *
FROM Produto
WHERE Codigo = 100;

ROLLBACK;


-- executa a mesma inserção e confirma
BEGIN TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

COMMIT;


-- testa uma exclusão e desfaz
BEGIN TRANSACTION;

DELETE FROM Produto
WHERE Codigo = 100;

ROLLBACK;


-- executa a exclusão e confirma
BEGIN TRANSACTION;

DELETE FROM Produto
WHERE Codigo = 100;

COMMIT;
```

### MySQL

```sql
START TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

ROLLBACK;


START TRANSACTION;

INSERT INTO Produto (Codigo, Nome, Preco)
VALUES (100, 'Teclado mecânico', 300);

COMMIT;
```

## Pontos que costumam gerar confusão

- **Uma transação é uma unidade lógica de trabalho, não apenas um comando SQL.** Ela pode reunir várias instruções que precisam funcionar como uma única ação.
- **`COMMIT` e `ROLLBACK` encerram a transação de maneiras diferentes.** `COMMIT` confirma; `ROLLBACK` desfaz.
- **Uma alteração pode aparecer antes do `COMMIT` e ainda assim ser desfeita.** Enquanto a transação não tiver sido confirmada, `ROLLBACK` pode cancelar suas alterações.
- **`ROLLBACK` pode desfazer inserções, exclusões e outras alterações da transação.**
- **Atomicidade significa tudo ou nada.** Uma operação composta, como transferência bancária, não deve permanecer parcialmente concluída.
- **SQL Server e MySQL não usam exatamente a mesma sintaxe para iniciar a transação.** Os exemplos usam `BEGIN TRANSACTION` no SQL Server e `START TRANSACTION` no MySQL.
- **O nome ACID é mais amplo do que atomicidade.** Neste ponto, a ideia explicitamente desenvolvida é a indivisibilidade da transação; as demais propriedades não são detalhadas aqui.
