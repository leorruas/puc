# Consultas aninhadas sem e com correlação

> **Contexto:** Este artigo apresenta subconsultas — também chamadas de consultas aninhadas ou *subqueries* — e mostra como uma consulta pode usar o resultado de outra consulta. O foco está em subconsultas escalares, listas produzidas por subqueries, operadores `IN`, `NOT IN`, `ANY`, `ALL`, subconsultas sem correlação, subconsultas correlacionadas e `EXISTS`.

Até aqui, as consultas foram construídas combinando filtros, agrupamentos e junções. Há situações, porém, em que uma pergunta depende primeiro da resposta de outra pergunta.

Por exemplo:

> quais produtos têm preço maior do que a média de todos os produtos?

Antes de decidir quais produtos mostrar, precisamos descobrir a média. Esse cálculo pode ser colocado dentro da própria consulta, formando uma **subconsulta**.

## 1. O que é uma subconsulta

Uma subconsulta é um bloco `SELECT` escrito dentro de outra consulta SQL.

A consulta mais externa é chamada de **consulta externa**. A consulta inserida entre parênteses é a **subconsulta**, **consulta aninhada** ou **subquery**.

Exemplo:

~~~sql
SELECT NomeProduto, Preco
FROM Produto
WHERE Preco > (
    SELECT AVG(Preco)
    FROM Produto
);
~~~

Podemos decompor a instrução assim:

| Parte | Papel |
| --- | --- |
| `SELECT AVG(Preco) FROM Produto` | calcula a média de preços |
| `Preco > (...)` | compara cada preço com o resultado da subconsulta |
| consulta externa | mostra os produtos que satisfazem a comparação |

O modelo mental inicial é:

> **a subconsulta produz um resultado; a consulta externa usa esse resultado como parte de sua própria condição.**

## 2. O resultado da subconsulta é uma tabela temporária

O resultado produzido por uma subconsulta existe durante a execução da consulta e pode assumir formatos diferentes.

| Forma do resultado | Exemplo de uso |
| --- | --- |
| uma linha e uma coluna | comparar com `=`, `>`, `<` etc. |
| várias linhas e uma coluna | comparar com `IN`, `NOT IN`, `ANY` ou `ALL` |
| várias linhas e várias colunas | usar a combinação retornada em uma condição compatível |

Uma subconsulta escalar retorna **um único valor**.

Por exemplo:

~~~sql
SELECT customer_id, first_name, last_name
FROM customer
WHERE customer_id = (
    SELECT MAX(customer_id)
    FROM customer
);
~~~

A subconsulta:

~~~sql
SELECT MAX(customer_id)
FROM customer
~~~

retorna um único valor. Esse valor é então usado pela consulta externa na comparação com `customer_id`.

## 3. Operadores usados com subconsultas

Quando a subconsulta retorna um único valor, podem ser usados os operadores de comparação já estudados:

| Operador | Leitura |
| --- | --- |
| `=` | igual |
| `<>` | diferente |
| `>` | maior |
| `<` | menor |
| `>=` | maior ou igual |
| `<=` | menor ou igual |

Quando a subconsulta retorna uma lista de valores, entram operadores como:

| Operador | Ideia central |
| --- | --- |
| `IN` | o valor aparece no conjunto retornado |
| `NOT IN` | o valor não aparece no conjunto retornado |
| `ANY` | a comparação é verdadeira para pelo menos um valor |
| `ALL` | a comparação precisa ser verdadeira para todos os valores |
| `EXISTS` | interessa saber se existe pelo menos uma linha |
| `NOT EXISTS` | interessa saber se não existe linha que satisfaça a condição |

## 4. `IN`: verificar se um valor pertence ao resultado

Considere a pergunta:

> quais cidades pertencem ao Canadá ou ao México?

A subconsulta pode primeiro obter os códigos desses países:

~~~sql
SELECT country_id
FROM country
WHERE country IN ('Canada', 'Mexico');
~~~

A consulta externa verifica quais cidades possuem um `country_id` presente nessa lista:

~~~sql
SELECT city_id, city
FROM city
WHERE country_id IN (
    SELECT country_id
    FROM country
    WHERE country IN ('Canada', 'Mexico')
);
~~~

O modelo mental é:

> **a subconsulta cria uma lista; `IN` pergunta se o valor da linha externa está dentro dessa lista.**

## 5. `NOT IN`: excluir os valores encontrados

Para obter as cidades que não pertencem ao Canadá nem ao México:

~~~sql
SELECT city_id, city
FROM city
WHERE country_id NOT IN (
    SELECT country_id
    FROM country
    WHERE country IN ('Canada', 'Mexico')
);
~~~

A estrutura é praticamente a mesma. O que muda é a lógica da condição:

- `IN`: manter o que pertence ao conjunto;
- `NOT IN`: manter o que não pertence ao conjunto.

## 6. `ALL`: a condição precisa valer para todos

`ALL` combina um operador de comparação com o conjunto retornado pela subconsulta.

Exemplo:

~~~sql
SELECT first_name, last_name
FROM customer
WHERE customer_id <> ALL (
    SELECT customer_id
    FROM payment
    WHERE amount = 0
);
~~~

A condição pode ser lida como:

> mantenha o cliente se seu `customer_id` for diferente de **todos** os códigos retornados pela subconsulta.

Nesse exemplo, a lógica é equivalente a:

~~~sql
SELECT first_name, last_name
FROM customer
WHERE customer_id NOT IN (
    SELECT customer_id
    FROM payment
    WHERE amount = 0
);
~~~

O modelo mental é:

> **`ALL` exige que a comparação seja satisfeita em relação a todos os valores do conjunto.**

## 7. `ANY`: basta um valor satisfazer a comparação

`ANY` também é combinado com um operador de comparação, mas sua lógica é diferente.

Considere uma subconsulta que produz vários totais de pagamento. Uma condição como:

~~~sql
HAVING SUM(amount) > ANY (
    SELECT SUM(p.amount)
    FROM payment AS p
    INNER JOIN customer AS c
        ON p.customer_id = c.customer_id
    INNER JOIN address AS a
        ON c.address_id = a.address_id
    INNER JOIN city AS ct
        ON a.city_id = ct.city_id
    INNER JOIN country AS co
        ON ct.country_id = co.country_id
    WHERE co.country IN ('Bolivia', 'Paraguay', 'Chile')
    GROUP BY co.country
);
~~~

pergunta se o total da consulta externa é maior do que **pelo menos um** dos totais retornados pela subconsulta.

A diferença essencial é:

| Operador | Quando a comparação é verdadeira? |
| --- | --- |
| `> ANY (...)` | quando é maior que pelo menos um valor |
| `> ALL (...)` | quando é maior que todos os valores |

## 8. Subconsulta sem correlação

Uma subconsulta é **sem correlação** quando não depende de nenhuma coluna da consulta externa.

Exemplo:

~~~sql
SELECT NomeProduto, Preco
FROM Produto
WHERE Preco > (
    SELECT AVG(Preco)
    FROM Produto
);
~~~

A consulta interna:

~~~sql
SELECT AVG(Preco)
FROM Produto;
~~~

pode ser executada isoladamente porque não precisa de nenhum valor fornecido pela consulta externa.

Isso fornece uma regra prática:

> **se a subconsulta consegue ser executada sozinha, ela pode ser uma subconsulta sem correlação.**

No exemplo, primeiro podemos imaginar o cálculo da média e depois a comparação de cada produto com esse valor.

## 9. Subconsulta com correlação

Uma subconsulta é **correlacionada** quando referencia uma coluna pertencente à consulta externa.

Considere a pergunta:

> quais produtos têm preço menor do que a média de preço da própria categoria?

A consulta pode ser escrita assim:

~~~sql
SELECT
    P.NomeProduto,
    P.Preco
FROM Produto AS P
WHERE P.Preco < (
    SELECT AVG(P2.Preco)
    FROM Produto AS P2
    WHERE P2.Categoria = P.Categoria
);
~~~

A parte decisiva é:

~~~sql
P2.Categoria = P.Categoria
~~~

`P2.Categoria` pertence à subconsulta. Já `P.Categoria` pertence à linha que está sendo examinada pela consulta externa.

## 10. Como pensar a execução de uma subconsulta correlacionada

O modelo mental útil é linha a linha.

Suponha que a tabela possua:

| Produto | Categoria | Preço |
| --- | --- | ---: |
| Computador AMD | 1 | 3500 |
| Computador Intel | 1 | 1000 |
| Impressora Epson | 2 | 1500 |
| Mouse | 3 | 80 |
| Mesa digitalizadora | 3 | 460 |

Para cada linha da consulta externa:

1. a consulta pega a categoria do produto atual;
2. essa categoria entra na condição da subconsulta;
3. a subconsulta calcula a média dos produtos daquela categoria;
4. o preço do produto atual é comparado com essa média;
5. se a condição for verdadeira, a linha entra no resultado.

Por exemplo, para `Computador Intel`:

~~~text
Categoria externa = 1
↓
subconsulta calcula AVG(Preco) apenas da categoria 1
↓
o preço 1000 é comparado com essa média
↓
se 1000 for menor, o produto é retornado
~~~

O ponto central é que **o valor da linha externa muda o resultado da consulta interna**.

## 11. Por que a subconsulta correlacionada não funciona sozinha

Considere apenas a subconsulta:

~~~sql
SELECT AVG(P2.Preco)
FROM Produto AS P2
WHERE P2.Categoria = P.Categoria;
~~~

Se ela for executada isoladamente, `P.Categoria` não possui significado, porque o alias `P` foi definido na consulta externa.

Essa dependência é justamente o que caracteriza a correlação.

A comparação fica assim:

| Tipo | Depende da consulta externa? | Pode ser entendida isoladamente? |
| --- | --- | --- |
| sem correlação | não | sim |
| com correlação | sim | não, porque usa valor da linha externa |

## 12. Outro exemplo de correlação: contar ocorrências

Considere:

~~~sql
SELECT c.first_name, c.last_name
FROM customer AS c
WHERE 20 = (
    SELECT COUNT(*)
    FROM rental AS r
    WHERE r.customer_id = c.customer_id
);
~~~

Para cada cliente da consulta externa, a subconsulta conta quantos aluguéis daquele cliente existem.

A correlação está em:

~~~sql
r.customer_id = c.customer_id
~~~

Se a contagem for igual a 20, o nome do cliente aparece no resultado.

## 13. `EXISTS`: interessa saber se existe pelo menos uma linha

Há perguntas em que não precisamos saber **quantas** linhas existem nem qual valor elas contêm. Basta saber se existe ao menos uma ocorrência que satisfaça a condição.

Exemplo:

~~~sql
SELECT c.first_name, c.last_name
FROM customer AS c
WHERE EXISTS (
    SELECT 1
    FROM rental AS r
    WHERE r.customer_id = c.customer_id
      AND DATE(r.rental_date) < '2005-05-25'
);
~~~

A consulta pergunta:

> existe pelo menos um aluguel desse cliente realizado antes de 25 de maio de 2005?

Se a resposta for verdadeira, o cliente entra no resultado.

## 14. Por que aparece `SELECT 1` dentro de `EXISTS`

Em:

~~~sql
EXISTS (
    SELECT 1
    FROM rental AS r
    WHERE ...
)
~~~

o valor `1` não representa uma contagem.

O que interessa para `EXISTS` é saber se a subconsulta encontra uma linha que satisfaça a condição. O conteúdo selecionado não é a informação principal usada pela consulta externa.

O modelo mental é:

> **`EXISTS` pergunta “há alguma linha que atende a isso?”**

## 15. `EXISTS` com correlação entre produto e fornecedor

Também podemos aplicar a mesma ideia ao exemplo de produtos e fornecedores.

Pergunta:

> quais produtos pertencem a fornecedores cuja cidade começa com “Belo”?

~~~sql
SELECT
    P.NomeProduto,
    P.Preco
FROM Produto AS P
WHERE EXISTS (
    SELECT 1
    FROM Fornecedor AS F
    WHERE F.CodigoFornecedor = P.Fornecedor
      AND F.Cidade LIKE 'Belo%'
);
~~~

A subconsulta depende da linha externa porque usa:

~~~sql
P.Fornecedor
~~~

Para cada produto, verifica-se se existe um fornecedor correspondente cuja cidade satisfaça o padrão.

## 16. Escolhendo o operador pelo formato da pergunta

Um jeito prático de escolher a construção é observar o que a consulta interna precisa devolver.

| Pergunta | Construção útil |
| --- | --- |
| preciso de um único valor? | subconsulta escalar + operador de comparação |
| preciso saber se um valor pertence a uma lista? | `IN` |
| preciso garantir que não pertence à lista? | `NOT IN` |
| preciso comparar com pelo menos um valor? | `ANY` |
| preciso comparar com todos os valores? | `ALL` |
| só preciso saber se há alguma linha? | `EXISTS` |
| a consulta interna precisa de um valor da linha externa? | subconsulta correlacionada |

Essa tabela não substitui a leitura da consulta, mas ajuda a transformar uma pergunta de negócio em uma estrutura SQL.

## 17. Relação com `JOIN`

Subconsulta e `JOIN` não são sinônimos.

No [[10. Cláusula JOIN, junções e UNION|artigo 10]], `JOIN` foi usado para combinar linhas de tabelas relacionadas e colocar suas colunas lado a lado.

Uma subconsulta pode ter outra função: produzir um valor, uma lista ou uma condição de existência usada pela consulta externa.

Além disso, uma própria subconsulta pode conter `JOIN`, como no exemplo com `ANY`.

O modelo mental é:

> **`JOIN` responde principalmente “como relaciono estas tabelas?”; a subconsulta responde “preciso usar o resultado de outra consulta dentro desta decisão?”.**

## 18. Script de prática

~~~sql
-- produtos com preço acima da média geral
SELECT NomeProduto, Preco
FROM Produto
WHERE Preco > (
    SELECT AVG(Preco)
    FROM Produto
);

-- cidades do Canadá ou México
SELECT city_id, city
FROM city
WHERE country_id IN (
    SELECT country_id
    FROM country
    WHERE country IN ('Canada', 'Mexico')
);

-- cidades fora do Canadá e México
SELECT city_id, city
FROM city
WHERE country_id NOT IN (
    SELECT country_id
    FROM country
    WHERE country IN ('Canada', 'Mexico')
);

-- comparação com ALL
SELECT first_name, last_name
FROM customer
WHERE customer_id <> ALL (
    SELECT customer_id
    FROM payment
    WHERE amount = 0
);

-- subconsulta correlacionada:
-- produto abaixo da média da própria categoria
SELECT
    P.NomeProduto,
    P.Preco
FROM Produto AS P
WHERE P.Preco < (
    SELECT AVG(P2.Preco)
    FROM Produto AS P2
    WHERE P2.Categoria = P.Categoria
);

-- cliente com exatamente 20 aluguéis
SELECT c.first_name, c.last_name
FROM customer AS c
WHERE 20 = (
    SELECT COUNT(*)
    FROM rental AS r
    WHERE r.customer_id = c.customer_id
);

-- cliente com pelo menos um aluguel antes da data indicada
SELECT c.first_name, c.last_name
FROM customer AS c
WHERE EXISTS (
    SELECT 1
    FROM rental AS r
    WHERE r.customer_id = c.customer_id
      AND DATE(r.rental_date) < '2005-05-25'
);

-- produtos de fornecedores cuja cidade começa com Belo
SELECT
    P.NomeProduto,
    P.Preco
FROM Produto AS P
WHERE EXISTS (
    SELECT 1
    FROM Fornecedor AS F
    WHERE F.CodigoFornecedor = P.Fornecedor
      AND F.Cidade LIKE 'Belo%'
);
~~~

## Pontos que costumam gerar confusão

- **Subconsulta e consulta externa não são duas instruções independentes no resultado final.** A subconsulta participa da construção da consulta maior.
- **Subconsulta escalar precisa produzir um valor compatível com a comparação feita pela consulta externa.**
- **`IN` e `NOT IN` trabalham com pertencimento a um conjunto retornado pela subconsulta.**
- **`ANY` e `ALL` têm lógicas diferentes.** `ANY` exige que a comparação funcione para pelo menos um valor; `ALL`, para todos.
- **Uma subconsulta sem correlação não depende da linha externa.** Ela pode ser entendida e executada isoladamente.
- **Uma subconsulta correlacionada depende de uma coluna da consulta externa.** O valor da linha externa participa da consulta interna.
- **O alias é essencial para distinguir a tabela externa da interna quando ambas usam a mesma tabela.**
- **`EXISTS` não pergunta quantas linhas existem.** Basta que a subconsulta encontre pelo menos uma linha que satisfaça a condição.
- **`SELECT 1` em `EXISTS` não significa “retorne a quantidade 1”.** O valor selecionado é apenas um conteúdo possível; o que interessa é a existência da linha.
- **Subconsultas podem conter `JOIN`, agrupamentos e outras construções SQL.** Elas continuam sendo consultas completas inseridas em outra consulta.
