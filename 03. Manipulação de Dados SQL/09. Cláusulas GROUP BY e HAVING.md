# Cláusulas `GROUP BY` e `HAVING`

> **Contexto:** Este artigo amplia o uso das funções agregadas ao permitir que cálculos como `COUNT`, `AVG` e `SUM` sejam feitos separadamente para diferentes grupos de linhas. `GROUP BY` define como os dados serão agrupados, enquanto `HAVING` permite filtrar os resultados agregados produzidos por esses grupos.

Uma agregação geral responde perguntas como “qual é o preço médio de todos os produtos?” ou “quantos fornecedores existem?”. Muitas análises, porém, precisam dividir os dados em partes: quantidade de fornecedores **por estado**, preço médio **por categoria** ou soma dos preços **por fornecedor**.

É nesse ponto que entra `GROUP BY`.

## 1. Da agregação geral para a agregação por grupo

Considere esta consulta:

```sql
SELECT COUNT(*)
FROM Fornecedor;
```

Ela produz uma única contagem para toda a tabela.

Se quisermos saber a quantidade de fornecedores em cada estado, precisamos separar as linhas por `UF`:

```sql
SELECT UF, COUNT(*)
FROM Fornecedor
GROUP BY UF;
```

Agora a contagem é calculada uma vez para cada grupo de fornecedores que compartilha o mesmo valor de `UF`.

O modelo mental é:

> **sem `GROUP BY`: uma agregação para o conjunto inteiro; com `GROUP BY`: uma agregação para cada grupo.**

## 2. Posição de `GROUP BY` e `HAVING` na consulta

Com as cláusulas estudadas até aqui, a estrutura pode ser organizada assim:

```sql
SELECT colunas_e_agregações
FROM tabela
WHERE condições
GROUP BY coluna
HAVING condições_sobre_os_grupos
ORDER BY coluna;
```

Nem todas as cláusulas precisam aparecer em toda consulta. Quando utilizadas juntas, `GROUP BY` aparece depois de `WHERE`, `HAVING` vem depois de `GROUP BY` e `ORDER BY` aparece ao final.

## 3. `GROUP BY`: agrupar linhas por um valor comum

Para contar fornecedores por estado:

```sql
SELECT UF, COUNT(*) AS QuantidadeFornecedores
FROM Fornecedor
GROUP BY UF;
```

Se existirem fornecedores da Bahia, Minas Gerais e São Paulo, cada valor distinto de `UF` forma um grupo. O `COUNT(*)` é calculado separadamente dentro de cada um deles.

Um resultado possível seria:

| UF | QuantidadeFornecedores |
| --- | ---: |
| BA | 2 |
| MG | 2 |
| SP | 2 |

O alias `QuantidadeFornecedores` apenas torna o nome da coluna resultante mais legível, como estudado em [[08. Funções agregadas e cálculos em SQL#3. Alias: dar um nome mais claro ao resultado|funções agregadas e aliases]].

## 4. Mostrar no resultado a coluna usada para agrupar

Também seria possível escrever:

```sql
SELECT COUNT(*)
FROM Fornecedor
GROUP BY UF;
```

A consulta ainda produz uma contagem para cada estado, mas o resultado não mostra qual `UF` corresponde a cada quantidade.

Por isso, quando queremos identificar visualmente cada grupo, incluímos a coluna de agrupamento no `SELECT`:

```sql
SELECT UF, COUNT(*)
FROM Fornecedor
GROUP BY UF;
```

Assim, cada resultado agregado aparece acompanhado do valor que identifica seu grupo.

## 5. Ordenando os grupos com `ORDER BY`

O resultado agrupado também pode ser ordenado.

Para ordenar alfabeticamente pelas UFs:

```sql
SELECT UF, COUNT(*) AS QuantidadeFornecedores
FROM Fornecedor
GROUP BY UF
ORDER BY UF;
```

A agregação continua sendo feita por estado; `ORDER BY` apenas organiza a apresentação final.

## 6. Ordenação pela posição da coluna no `SELECT`

Também é possível indicar em `ORDER BY` a posição da expressão desejada na lista do `SELECT`.

Considere:

```sql
SELECT UF, COUNT(*)
FROM Fornecedor
GROUP BY UF
ORDER BY 2;
```

Na lista do `SELECT`:

1. `UF` ocupa a primeira posição;
2. `COUNT(*)` ocupa a segunda.

Por isso, `ORDER BY 2` ordena pelo resultado de `COUNT(*)`.

Da mesma forma:

```sql
ORDER BY 1;
```

ordena pela primeira expressão do `SELECT`, que nesse caso é `UF`.

## 7. `AVG` com `GROUP BY`: média por categoria

As funções agregadas estudadas anteriormente podem ser combinadas com agrupamento.

Para calcular o preço médio dos produtos de cada categoria:

```sql
SELECT Categoria, AVG(Preco) AS PrecoMedio
FROM Produto
GROUP BY Categoria;
```

Sem `GROUP BY`, `AVG(Preco)` produziria uma única média para todos os produtos. Com `GROUP BY Categoria`, cada categoria recebe sua própria média.

Um resultado pode ter a forma:

| Categoria | PrecoMedio |
| --- | ---: |
| 1 | 2250 |
| 2 | 1500 |
| 3 | 270 |

Neste ponto, a consulta trabalha apenas com o código da categoria armazenado em `Produto`. A recuperação do nome da categoria a partir de outra tabela exige relacionar tabelas, assunto que será tratado posteriormente.

## 8. `HAVING`: filtrar resultados agregados

Depois de agrupar e calcular uma função agregada, pode ser necessário exibir somente os grupos que atendem a determinada condição.

Por exemplo: mostrar apenas categorias cujo preço médio seja superior a 1000.

```sql
SELECT Categoria, AVG(Preco) AS PrecoMedio
FROM Produto
GROUP BY Categoria
HAVING AVG(Preco) > 1000;
```

Primeiro os produtos são agrupados por categoria e a média é calculada para cada grupo. Depois, `HAVING` mantém somente os grupos cuja média satisfaz a condição.

No exemplo anterior, a categoria com média de `270` seria excluída do resultado.

## 9. `WHERE` e `HAVING` têm funções diferentes

As duas cláusulas aplicam condições, mas atuam em momentos conceitualmente diferentes da consulta.

| Cláusula | O que filtra? |
| --- | --- |
| `WHERE` | linhas que participarão da consulta |
| `HAVING` | grupos ou resultados agregados |

Considere:

```sql
SELECT Categoria, AVG(Preco) AS PrecoMedio
FROM Produto
WHERE Preco IS NOT NULL
GROUP BY Categoria
HAVING AVG(Preco) > 1000;
```

Aqui:

- `WHERE Preco IS NOT NULL` restringe as linhas consideradas;
- `GROUP BY Categoria` forma os grupos;
- `AVG(Preco)` calcula uma média para cada grupo;
- `HAVING AVG(Preco) > 1000` filtra os grupos segundo o valor agregado.

O modelo mental é:

> **`WHERE` filtra linhas; `GROUP BY` forma grupos; funções agregadas resumem os grupos; `HAVING` filtra os resultados desses grupos.**

## 10. Operadores também podem ser usados em `HAVING`

As condições de `HAVING` podem utilizar operadores de comparação já estudados.

Por exemplo:

```sql
SELECT Categoria, AVG(Preco) AS PrecoMedio
FROM Produto
GROUP BY Categoria
HAVING AVG(Preco) < 1000;
```

ou:

```sql
SELECT Categoria, AVG(Preco) AS PrecoMedio
FROM Produto
GROUP BY Categoria
HAVING AVG(Preco) >= 1000;
```

Assim, os operadores de [[07. Operadores e condições em consultas SQL|comparação e condições]] também participam de filtros aplicados aos valores agregados.

## 11. `SUM` com agrupamento

O mesmo padrão funciona com `SUM`.

Para calcular a soma dos preços dos produtos de cada fornecedor:

```sql
SELECT Fornecedor, SUM(Preco) AS SomaPrecos
FROM Produto
GROUP BY Fornecedor;
```

Cada valor distinto de `Fornecedor` forma um grupo, e `SUM(Preco)` calcula o total correspondente a cada um.

Isso responde uma pergunta diferente de:

```sql
SELECT SUM(Preco)
FROM Produto;
```

A primeira consulta produz um total **por fornecedor**; a segunda produz um único total **para todos os produtos**.

## 12. O padrão de análise

As consultas desta etapa seguem um encadeamento útil:

```text
linhas
  → filtro opcional
  → grupos
  → cálculo agregado por grupo
  → filtro dos grupos
  → ordenação do resultado
```

Em SQL:

```sql
SELECT coluna_grupo, FUNCAO_AGREGADA(coluna)
FROM tabela
WHERE condição_opcional
GROUP BY coluna_grupo
HAVING condição_sobre_agregação
ORDER BY coluna;
```

Esse padrão permite responder perguntas como:

- quantos fornecedores existem por estado?
- qual é o preço médio por categoria?
- quais categorias possuem preço médio acima de determinado valor?
- qual é a soma dos preços por fornecedor?

## 13. Script de prática

```sql
-- quantidade total de fornecedores
SELECT COUNT(*) AS QuantidadeFornecedores
FROM Fornecedor;

-- quantidade de fornecedores por estado
SELECT UF, COUNT(*) AS QuantidadeFornecedores
FROM Fornecedor
GROUP BY UF;

-- quantidade por estado em ordem alfabética
SELECT UF, COUNT(*) AS QuantidadeFornecedores
FROM Fornecedor
GROUP BY UF
ORDER BY UF;

-- ordenação pela segunda expressão do SELECT
SELECT UF, COUNT(*)
FROM Fornecedor
GROUP BY UF
ORDER BY 2;

-- média de preços por categoria
SELECT Categoria, AVG(Preco) AS PrecoMedio
FROM Produto
GROUP BY Categoria;

-- somente categorias com média acima de 1000
SELECT Categoria, AVG(Preco) AS PrecoMedio
FROM Produto
GROUP BY Categoria
HAVING AVG(Preco) > 1000;

-- somente categorias com média abaixo de 1000
SELECT Categoria, AVG(Preco) AS PrecoMedio
FROM Produto
GROUP BY Categoria
HAVING AVG(Preco) < 1000;

-- soma dos preços por fornecedor
SELECT Fornecedor, SUM(Preco) AS SomaPrecos
FROM Produto
GROUP BY Fornecedor;
```

## Pontos que costumam gerar confusão

- **Função agregada sem `GROUP BY` resume o conjunto inteiro; com `GROUP BY`, resume cada grupo separadamente.**
- **A coluna de agrupamento pode aparecer no `SELECT` para identificar cada grupo no resultado.**
- **`WHERE` e `HAVING` não são equivalentes.** `WHERE` restringe linhas; `HAVING` filtra grupos ou resultados agregados.
- **`HAVING` aparece depois de `GROUP BY`.** Ele pode aplicar condições a expressões como `AVG(Preco)`.
- **`ORDER BY` continua sendo responsável apenas pela ordenação do resultado.**
- **`ORDER BY 2` significa ordenar pela segunda expressão da lista do `SELECT`.**
- **`SUM(Preco)` e `SUM(Preco) ... GROUP BY Fornecedor` respondem perguntas diferentes.** O primeiro produz um total geral; o segundo produz um total para cada fornecedor.
