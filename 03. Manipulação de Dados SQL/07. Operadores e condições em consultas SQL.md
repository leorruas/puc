# Operadores e condições em consultas SQL

> **Contexto:** Este artigo amplia o uso de `SELECT` e `WHERE` com operadores e condições usados para filtrar dados. O material da disciplina organiza esses recursos em comparação, lógica e texto. Em terminologia SQL mais precisa, alguns elementos apresentados como “operadores”, como `BETWEEN`, `IN`, `IS NULL` e `LIKE`, funcionam como predicados: expressões que avaliam uma condição e determinam se uma linha participa ou não do resultado.

No [[06. Comando SELECT|artigo 06]], `WHERE` apareceu como a cláusula responsável por restringir as linhas retornadas por uma consulta. Agora é possível enriquecer essas condições com comparações, combinações lógicas, intervalos, listas, testes de nulidade e padrões de texto.

O modelo mental é simples: **`SELECT` define o que mostrar; `FROM` indica de onde vêm os dados; `WHERE` decide quais linhas passam pelo filtro; e os operadores ou predicados expressam a regra desse filtro**.

## 1. Operadores de comparação

Os operadores de comparação confrontam um valor de uma coluna com outro valor.

| Operador | Significado |
| --- | --- |
| `=` | igual a |
| `<>` | diferente de |
| `>` | maior que |
| `<` | menor que |
| `>=` | maior ou igual a |
| `<=` | menor ou igual a |

Considere uma tabela `Produto` com colunas como `Nome`, `Preco` e `Categoria`.

### Igualdade

Para recuperar produtos da categoria `3`:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Categoria = '3';
```

A coluna utilizada no filtro **não precisa aparecer no `SELECT`**. Podemos filtrar por `Categoria` e retornar apenas `Nome` e `Preco`.

Se quisermos conferir também a categoria:

```sql
SELECT Nome, Preco, Categoria
FROM Produto
WHERE Categoria = '3';
```

Essa distinção é importante: a lista do `SELECT` controla **o que aparece no resultado**; a condição do `WHERE` controla **quais linhas aparecem**.

### Diferente de

Para excluir a categoria `3` do resultado:

```sql
SELECT Nome, Categoria
FROM Produto
WHERE Categoria <> '3';
```

O operador `<>` é a forma de “diferente de” apresentada no material da disciplina.

### Maior, menor e limites inclusivos

Para recuperar produtos com preço maior que 1000:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco > 1000;
```

Para recuperar produtos com preço menor ou igual a 1000:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco <= 1000;
```

O sinal de igualdade muda a fronteira do filtro. Em `Preco < 1000`, o valor `1000` fica de fora; em `Preco <= 1000`, ele pode aparecer no resultado.

## 2. Comparação e ordenação são coisas diferentes

Filtrar não é o mesmo que ordenar.

Esta consulta escolhe apenas os produtos com preço maior que 1000:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco > 1000;
```

Se também quisermos organizar o resultado pelo preço:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco > 1000
ORDER BY Preco;
```

No comportamento padrão apresentado na aula, a ordenação é crescente. Para inverter:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco > 1000
ORDER BY Preco DESC;
```

Assim, `WHERE` define **quais linhas entram** e `ORDER BY` define **em que ordem elas aparecem**.

## 3. `AND`: todas as condições precisam ser verdadeiras

`AND` combina condições e exige que todas sejam satisfeitas.

Para recuperar produtos com preço entre 1000 e 2000, incluindo os extremos:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco >= 1000
  AND Preco <= 2000;
```

Uma linha só aparece se atender simultaneamente às duas comparações.

Podemos ler:

> preço maior ou igual a 1000 **e** preço menor ou igual a 2000.

## 4. `OR`: basta uma condição ser verdadeira

`OR` combina alternativas. A linha pode ser retornada quando pelo menos uma das condições é satisfeita.

Por exemplo:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco = 80
   OR Preco = 1000;
```

A consulta aceita produtos cujo preço seja `80` **ou** `1000`.

A diferença fundamental é:

- `AND`: todas as condições combinadas precisam ser verdadeiras;
- `OR`: basta uma das condições combinadas ser verdadeira.

## 5. `BETWEEN`: filtrar por intervalo

Quando existe um limite inferior e um limite superior, `BETWEEN` oferece uma forma mais compacta de escrever o intervalo.

Estas duas consultas expressam a mesma ideia:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco >= 1000
  AND Preco <= 2000;
```

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco BETWEEN 1000 AND 2000;
```

No material da disciplina, `BETWEEN` é apresentado com uma característica essencial: **os limites são incluídos**.

Portanto:

```sql
WHERE Preco BETWEEN 1000 AND 2000
```

pode incluir tanto `1000` quanto `2000`.

## 6. `IN`: comparar com uma lista de valores

`IN` verifica se o valor de uma coluna pertence a uma lista.

Por exemplo:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco IN (80, 1000);
```

A linha é retornada quando `Preco` corresponde a qualquer um dos valores listados.

O mesmo raciocínio pode ser aplicado a texto:

```sql
SELECT Nome
FROM Categoria
WHERE Nome IN ('Acessórios', 'Suprimentos');
```

Em vez de escrever várias comparações ligadas por `OR`, podemos expressar diretamente a ideia de pertencimento a uma lista.

## 7. `NOT`: negar uma condição

`NOT` inverte o sentido lógico de uma condição.

Com `IN`:

```sql
SELECT Nome
FROM Categoria
WHERE Nome NOT IN ('Acessórios', 'Suprimentos');
```

Agora o resultado contém as categorias cujo nome **não pertence** à lista.

O ponto central é que `NOT` representa negação: queremos as linhas que não satisfazem a condição indicada.

## 8. `NULL` precisa de `IS NULL`

`NULL` representa ausência de valor. Por isso, a verificação apresentada na disciplina não utiliza `=`.

Para localizar produtos sem preço:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco IS NULL;
```

Para localizar produtos que possuem preço:

```sql
SELECT Nome, Preco
FROM Produto
WHERE Preco IS NOT NULL;
```

A distinção é:

- `IS NULL`: ausência de valor;
- `IS NOT NULL`: existe algum valor não nulo.

Isso se conecta ao conceito de `NULL` estudado em [[05. Comandos INSERT, UPDATE e DELETE#Quando a coluna aceita `NULL`|INSERT, UPDATE e DELETE]].

## 9. `LIKE`: procurar padrões em texto

Quando sabemos exatamente o texto procurado, podemos usar igualdade:

```sql
SELECT Nome, Cidade
FROM Fornecedor
WHERE Cidade = 'Belo Horizonte';
```

Mas pode acontecer de sabermos apenas uma parte do conteúdo. Nesse caso, o material apresenta `LIKE`, usado em conjunto com caracteres curinga (*wildcards*).

Os dois curingas estudados são:

| Curinga | Significado |
| --- | --- |
| `%` | nenhum, um ou vários caracteres |
| `_` | exatamente um caractere |

### Começa com determinado texto

Se sabemos que a cidade começa com `Belo`:

```sql
SELECT Nome, Cidade
FROM Fornecedor
WHERE Cidade LIKE 'Belo%';
```

O `%` aceita qualquer sequência depois de `Belo`.

### Termina com determinado texto

Se sabemos que termina com `Horizonte`:

```sql
SELECT Nome, Cidade
FROM Fornecedor
WHERE Cidade LIKE '%Horizonte';
```

### Contém determinado trecho

Se queremos um texto que contenha `Ho` em alguma posição:

```sql
SELECT Nome, Cidade
FROM Fornecedor
WHERE Cidade LIKE '%Ho%';
```

O primeiro `%` permite qualquer sequência antes; o segundo permite qualquer sequência depois.

### Exatamente um caractere com `_`

O sublinhado substitui uma única posição:

```sql
SELECT Nome, Cidade
FROM Fornecedor
WHERE Cidade LIKE '_elo Horizonte';
```

Esse padrão pode corresponder a `Belo Horizonte` porque `_` ocupa exatamente o lugar do `B`.

## 10. `LIKE` não é o mesmo que `=`

Os curingas `%` e `_` possuem significado especial quando usados com `LIKE`.

Por exemplo:

```sql
WHERE Cidade LIKE '%Horizonte'
```

procura textos que terminem em `Horizonte`.

Já:

```sql
WHERE Cidade = '%Horizonte'
```

não expressa a mesma busca por padrão. Nesse caso, o valor está sendo comparado como texto literal pela igualdade, e não como um padrão de `LIKE`.

Por isso, **usar um curinga exige o predicado adequado**.

## 11. Espaços também fazem parte do texto

Na busca por padrões, espaços contam como caracteres.

Considere:

```sql
WHERE Cidade LIKE '% Horizonte'
```

Esse espaço antes de `Horizonte` faz parte do padrão procurado.

Adicionar ou remover espaços pode mudar completamente o resultado. Isso reforça uma distinção já estudada: espaço é um caractere; `NULL` é ausência de valor.

## 12. Visão consolidada

Os recursos estudados podem ser organizados assim:

| Grupo didático | Recursos | Uso principal |
| --- | --- | --- |
| Comparação | `=`, `<>`, `>`, `<`, `>=`, `<=` | comparar valores |
| Lógica e condições | `AND`, `OR`, `NOT`, `BETWEEN`, `IN`, `IS NULL`, `IS NOT NULL` | combinar, negar ou especializar filtros |
| Texto | `LIKE`, `%`, `_` | buscar padrões em strings |

A classificação acima segue a organização didática do material. Em uma terminologia mais formal, `AND`, `OR` e `NOT` são operadores lógicos, enquanto construções como `BETWEEN`, `IN`, `IS NULL` e `LIKE` podem ser tratadas como predicados que produzem condições verdadeiras, falsas ou, em alguns contextos SQL, desconhecidas.

## 13. Script de prática

O script abaixo reúne exemplos dos principais filtros apresentados:

```sql
-- produtos da categoria 3
SELECT Nome, Preco
FROM Produto
WHERE Categoria = '3';

-- produtos que não pertencem à categoria 3
SELECT Nome, Categoria
FROM Produto
WHERE Categoria <> '3';

-- produtos com preço maior que 1000
SELECT Nome, Preco
FROM Produto
WHERE Preco > 1000
ORDER BY Preco;

-- produtos com preço menor ou igual a 1000,
-- ordenados do maior preço para o menor
SELECT Nome, Preco
FROM Produto
WHERE Preco <= 1000
ORDER BY Preco DESC;

-- intervalo inclusivo usando AND
SELECT Nome, Preco
FROM Produto
WHERE Preco >= 1000
  AND Preco <= 2000;

-- o mesmo intervalo com BETWEEN
SELECT Nome, Preco
FROM Produto
WHERE Preco BETWEEN 1000 AND 2000;

-- valores presentes em uma lista
SELECT Nome
FROM Categoria
WHERE Nome IN ('Acessórios', 'Suprimentos');

-- valores que não pertencem à lista
SELECT Nome
FROM Categoria
WHERE Nome NOT IN ('Acessórios', 'Suprimentos');

-- produtos sem preço
SELECT Nome, Preco
FROM Produto
WHERE Preco IS NULL;

-- produtos com preço informado
SELECT Nome, Preco
FROM Produto
WHERE Preco IS NOT NULL;

-- cidades que começam com Belo
SELECT Nome, Cidade
FROM Fornecedor
WHERE Cidade LIKE 'Belo%';

-- cidades que terminam com Horizonte
SELECT Nome, Cidade
FROM Fornecedor
WHERE Cidade LIKE '%Horizonte';

-- um caractere qualquer antes de "elo Horizonte"
SELECT Nome, Cidade
FROM Fornecedor
WHERE Cidade LIKE '_elo Horizonte';
```

## Pontos que costumam gerar confusão

- **A coluna usada no `WHERE` não precisa aparecer no `SELECT`.** Uma coluna pode participar do filtro sem ser exibida no resultado.
- **`>` e `>=` não são equivalentes.** O segundo inclui o valor de referência; o primeiro não.
- **`BETWEEN` inclui os dois extremos no exemplo estudado.** `BETWEEN 1000 AND 2000` pode retornar tanto `1000` quanto `2000`.
- **`AND` exige todas as condições; `OR` aceita alternativas.**
- **`IN` compara um valor com uma lista.** `NOT IN` expressa a negação dessa pertença.
- **`NULL` não deve ser testado com `= NULL`.** Para os casos estudados, usam-se `IS NULL` e `IS NOT NULL`.
- **`LIKE` é usado para padrões de texto.** Com `=`, `%` não funciona como curinga.
- **`%` e `_` têm comportamentos diferentes.** `%` aceita uma sequência de tamanho variável; `_` corresponde a exatamente uma posição.
- **Espaços fazem parte da string.** Um espaço inserido no padrão pode alterar o resultado da busca.
- **`WHERE` filtra; `ORDER BY` ordena.** Uma cláusula não substitui a outra.
