# Cláusula `JOIN`, junções e `UNION`

> **Contexto:** Este artigo mostra como combinar dados distribuídos em diferentes tabelas. `JOIN` relaciona linhas por meio de uma condição, normalmente ligando chave estrangeira e chave primária. Também são apresentados os principais tipos de junção, aliases de tabela, produto cartesiano, `UNION`, `UNION ALL` e `DISTINCT`.

Em bancos relacionais, uma informação completa costuma estar distribuída entre várias tabelas. A tabela `Produto`, por exemplo, pode guardar o código do fornecedor, enquanto o nome desse fornecedor fica na tabela `Fornecedor`. Para responder a uma pergunta que precisa das duas informações ao mesmo tempo, é necessário **juntar as tabelas**.

## 1. Modelo mental: relacionar tabelas por uma condição

Uma junção normalmente usa uma **chave estrangeira (FK)** de uma tabela e a chave primária correspondente (**PK**) de outra.

| Tabela `Fornecedor` | Papel |
| --- | --- |
| `CodigoFornecedor` | PK — identifica um fornecedor |
| `NomeFornecedor` | dado descritivo do fornecedor |

| Tabela `Produto` | Papel |
| --- | --- |
| `NomeProduto` | nome do produto |
| `Fornecedor` | FK — guarda o código do fornecedor associado |

A condição que conecta as duas tabelas é:

~~~sql
Produto.Fornecedor = Fornecedor.CodigoFornecedor
~~~

Em uma consulta:

~~~sql
SELECT
    Produto.NomeProduto,
    Fornecedor.NomeFornecedor
FROM Produto
JOIN Fornecedor
    ON Produto.Fornecedor = Fornecedor.CodigoFornecedor;
~~~

A cláusula `ON` informa **como as linhas das tabelas correspondem entre si**. Já `WHERE` continua sendo usada para filtrar linhas depois que a relação foi estabelecida.

A forma geral é:

~~~sql
SELECT colunas
FROM TabelaA
JOIN TabelaB
    ON TabelaA.coluna = TabelaB.coluna;
~~~

Também é possível encadear várias junções. A sintaxe antiga com tabelas separadas por vírgula no `FROM` e condição no `WHERE` pode produzir resultado equivalente em junções internas simples, mas `JOIN ... ON` deixa mais clara a separação entre relacionamento e filtro.

## 2. Tipos de junção

Considere estas tabelas:

### Tabela `Categoria`

| Codigo | Nome |
| --- | --- |
| C1 | Computadores |
| C2 | Impressoras |
| C3 | Acessórios |
| C4 | Suprimentos |

### Tabela `Produto`

| NomeProduto | Categoria |
| --- | --- |
| Computador AMD | C1 |
| Computador Intel | C1 |
| Impressora Epson | C2 |
| Mouse | C3 |
| Mesa digitalizadora | C3 |
| HD externo 1 TB | `NULL` |

Os tipos de junção diferem principalmente por **quais linhas sem correspondência são preservadas**:

| Tipo | Regra |
| --- | --- |
| `INNER JOIN` | somente linhas com correspondência |
| `LEFT JOIN` | correspondências + todas as linhas da esquerda |
| `RIGHT JOIN` | correspondências + todas as linhas da direita |
| `FULL OUTER JOIN` | correspondências + linhas não correspondentes dos dois lados |

**`INNER JOIN`** retorna apenas combinações em que a condição encontra correspondência nos dois lados. A palavra `INNER` pode ser omitida:

~~~sql
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
JOIN Produto AS P
    ON P.Categoria = C.Codigo;
~~~

Resultado:

| Categoria | Produto |
| --- | --- |
| Computadores | Computador AMD |
| Computadores | Computador Intel |
| Impressoras | Impressora Epson |
| Acessórios | Mouse |
| Acessórios | Mesa digitalizadora |

**`LEFT JOIN`** preserva todas as linhas da tabela à esquerda:

~~~sql
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
LEFT JOIN Produto AS P
    ON P.Categoria = C.Codigo;
~~~

| Categoria | Produto |
| --- | --- |
| Computadores | Computador AMD |
| Computadores | Computador Intel |
| Impressoras | Impressora Epson |
| Acessórios | Mouse |
| Acessórios | Mesa digitalizadora |
| Suprimentos | `NULL` |

**`RIGHT JOIN`** preserva todas as linhas da tabela à direita:

~~~sql
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
RIGHT JOIN Produto AS P
    ON P.Categoria = C.Codigo;
~~~

| Categoria | Produto |
| --- | --- |
| Computadores | Computador AMD |
| Computadores | Computador Intel |
| Impressoras | Impressora Epson |
| Acessórios | Mouse |
| Acessórios | Mesa digitalizadora |
| `NULL` | HD externo 1 TB |

**`FULL OUTER JOIN`** preserva os dois lados. No exemplo, o resultado incluiria tanto `Suprimentos` quanto o HD externo sem categoria.

> **Diferença entre SGBDs:** MySQL não implementa diretamente `FULL OUTER JOIN`. Uma alternativa é combinar `LEFT JOIN` e `RIGHT JOIN` com `UNION`.

A teoria dos conjuntos ajuda a formar o modelo mental, mas `JOIN` combina **linhas e colunas segundo uma condição**. Por isso, um `LEFT JOIN` não é literalmente apenas “a diferença do conjunto da esquerda”; ele também contém as correspondências.

## 3. Aliases e produto cartesiano

Quando várias tabelas aparecem na mesma consulta, aliases tornam a leitura mais curta:

~~~sql
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
JOIN Produto AS P
    ON P.Categoria = C.Codigo;
~~~

`C` é o alias de `Categoria` e `P` é o alias de `Produto`. O alias vale apenas dentro da consulta e não renomeia a tabela no banco.

Se duas tabelas forem combinadas sem uma relação que limite as correspondências, pode surgir um **produto cartesiano**. Em `CROSS JOIN`, esse comportamento é explícito:

### Tabela T1

| Valor |
| --- |
| A |
| B |

### Tabela T2

| Valor |
| --- |
| 1 |
| 2 |
| 3 |

~~~sql
SELECT T1.Valor, T2.Valor
FROM T1
CROSS JOIN T2;
~~~

| T1 | T2 |
| --- | --- |
| A | 1 |
| A | 2 |
| A | 3 |
| B | 1 |
| B | 2 |
| B | 3 |

Duas linhas de um lado e três do outro produzem `2 × 3 = 6` combinações. O produto cartesiano pode ser desejado, mas também pode indicar que faltou uma condição de junção.

## 4. `JOIN`, `UNION` e duplicidades

`JOIN` e `UNION` combinam dados de maneiras diferentes:

| Operação | O que faz? | Modelo mental |
| --- | --- | --- |
| `JOIN` | combina colunas de linhas relacionadas | coloca informações lado a lado |
| `UNION` | combina resultados compatíveis | empilha linhas |
| `UNION ALL` | empilha resultados sem remover repetições | mantém todas as linhas |
| `DISTINCT` | remove repetições dentro de um `SELECT` | mantém apenas linhas distintas |

Considere:

### Resultado A

| Valor |
| --- |
| 1 |
| 2 |

### Resultado B

| Valor |
| --- |
| 2 |
| 3 |

Com `UNION`:

~~~sql
SELECT Valor FROM A
UNION
SELECT Valor FROM B;
~~~

o resultado é:

| Valor |
| --- |
| 1 |
| 2 |
| 3 |

Com `UNION ALL`:

~~~sql
SELECT Valor FROM A
UNION ALL
SELECT Valor FROM B;
~~~

o resultado é:

| Valor |
| --- |
| 1 |
| 2 |
| 2 |
| 3 |

Os `SELECT` combinados precisam produzir o mesmo número de colunas em posições compatíveis.

`DISTINCT` atua dentro de um único `SELECT`:

~~~sql
SELECT DISTINCT C.Nome
FROM Categoria AS C
JOIN Produto AS P
    ON P.Categoria = C.Codigo;
~~~

Se `ORDER BY` aparece depois de um `UNION`, ele organiza o **resultado combinado**:

~~~sql
SELECT C.Nome AS Nome
FROM Categoria AS C
UNION
SELECT P.NomeProduto AS Nome
FROM Produto AS P
ORDER BY Nome;
~~~

No MySQL, uma aproximação de `FULL OUTER JOIN` pode ser construída assim:

~~~sql
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
LEFT JOIN Produto AS P
    ON P.Categoria = C.Codigo

UNION

SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
RIGHT JOIN Produto AS P
    ON P.Categoria = C.Codigo;
~~~

O uso de `UNION`, em vez de `UNION ALL`, evita repetir as linhas correspondentes que aparecem nos dois lados.

## 5. Script de prática

~~~sql
-- INNER JOIN
SELECT
    P.NomeProduto AS Produto,
    F.NomeFornecedor AS Fornecedor
FROM Produto AS P
JOIN Fornecedor AS F
    ON P.Fornecedor = F.CodigoFornecedor;

-- LEFT JOIN
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
LEFT JOIN Produto AS P
    ON P.Categoria = C.Codigo;

-- RIGHT JOIN
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
RIGHT JOIN Produto AS P
    ON P.Categoria = C.Codigo;

-- CROSS JOIN
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
CROSS JOIN Produto AS P;

-- UNION
SELECT C.Nome AS Nome
FROM Categoria AS C
UNION
SELECT P.NomeProduto AS Nome
FROM Produto AS P;

-- UNION ALL
SELECT C.Nome AS Nome
FROM Categoria AS C
UNION ALL
SELECT P.NomeProduto AS Nome
FROM Produto AS P;

-- DISTINCT
SELECT DISTINCT C.Nome AS Categoria
FROM Categoria AS C
JOIN Produto AS P
    ON P.Categoria = C.Codigo;
~~~

## Pontos que costumam gerar confusão

- **`JOIN` não significa simplesmente “colocar duas tabelas juntas”.** A condição em `ON` define quais linhas correspondem.
- **`INNER JOIN` e `JOIN` são equivalentes nos exemplos estudados.**
- **A ordem importa em `LEFT JOIN` e `RIGHT JOIN`.** “Esquerda” e “direita” se referem à posição das tabelas no `FROM`.
- **Linhas sem correspondência aparecem com `NULL` no lado ausente em junções externas.**
- **`CROSS JOIN` produz produto cartesiano.**
- **`JOIN` e `UNION` fazem coisas diferentes.** Um combina colunas relacionadas; o outro empilha linhas.
- **`UNION` remove duplicidades; `UNION ALL` preserva todas as linhas.**
- **`DISTINCT` elimina repetições dentro de um `SELECT`.**
- **MySQL não implementa `FULL OUTER JOIN` diretamente.**
- **Alias de tabela não renomeia a tabela no banco.**
