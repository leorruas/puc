# Cláusula `JOIN`, junções e `UNION`

> **Contexto:** Este artigo mostra como combinar dados distribuídos em diferentes tabelas. `JOIN` relaciona linhas por meio de uma condição, normalmente ligando chave estrangeira e chave primária. Também são apresentados `INNER JOIN`, `LEFT JOIN`, `RIGHT JOIN`, `FULL JOIN`, `CROSS JOIN`, aliases de tabela, `UNION`, `UNION ALL` e `DISTINCT`.

Em bancos relacionais, uma informação completa costuma estar distribuída entre várias tabelas. A tabela `Produto`, por exemplo, pode guardar o código do fornecedor, enquanto o nome desse fornecedor fica na tabela `Fornecedor`. Para responder a uma pergunta que precisa das duas informações ao mesmo tempo, é necessário **juntar as tabelas**.

A cláusula `JOIN` faz exatamente isso: combina linhas de duas ou mais tabelas a partir de uma relação definida na consulta.

## 1. Por que `JOIN` existe

Considere uma pergunta simples:

> quais produtos pertencem a quais fornecedores?

Se `NomeProduto` estiver em `Produto` e `NomeFornecedor` estiver em `Fornecedor`, nenhuma das tabelas isoladamente possui toda a resposta.

O modelo mental é:

> **cada tabela guarda uma parte da informação; o `JOIN` reconstrói a visão necessária para a consulta.**

Isso também explica por que consultas reais podem envolver várias tabelas ao mesmo tempo: produtos, clientes, vendedores, canais de venda e datas podem estar separados para evitar repetição e preservar a organização relacional.

## 2. A ligação mais comum: chave estrangeira com chave primária

Uma junção normalmente usa uma **chave estrangeira (FK)** de uma tabela e a chave primária correspondente (**PK**) de outra.

Uma reconstrução do relacionamento entre `Fornecedor` e `Produto` pode ser lida assim:

| Tabela `Fornecedor` | Papel |
| --- | --- |
| `CodigoFornecedor` | PK — identifica um fornecedor |
| `NomeFornecedor` | dado descritivo do fornecedor |

| Tabela `Produto` | Papel |
| --- | --- |
| `NomeProduto` | nome do produto |
| `Fornecedor` | FK — guarda o código do fornecedor associado |

A condição que conecta as duas tabelas é:

```sql
Produto.Fornecedor = Fornecedor.CodigoFornecedor
```

Em um `JOIN`:

```sql
SELECT
    Produto.NomeProduto,
    Fornecedor.NomeFornecedor
FROM Produto
JOIN Fornecedor
    ON Produto.Fornecedor = Fornecedor.CodigoFornecedor;
```

A cláusula `ON` informa **qual relação deve ser usada para decidir quais linhas correspondem entre si**.

## 3. Sintaxe de `JOIN`

A forma geral é:

```sql
SELECT colunas
FROM TabelaA
JOIN TabelaB
    ON TabelaA.coluna = TabelaB.coluna;
```

Também é possível encadear várias junções:

```sql
SELECT colunas
FROM TabelaA
JOIN TabelaB
    ON TabelaA.chave = TabelaB.chave_estrangeira
JOIN TabelaC
    ON TabelaB.outra_chave = TabelaC.chave;
```

Depois das junções, outras cláusulas continuam disponíveis:

```sql
SELECT colunas
FROM TabelaA
JOIN TabelaB
    ON condição_de_junção
WHERE condição_de_filtro
GROUP BY coluna
HAVING condição_sobre_grupo
ORDER BY coluna;
```

A distinção importante é:

- `ON`: define **como as tabelas se relacionam**;
- `WHERE`: filtra **quais linhas do resultado serão mantidas**.

## 4. Sintaxe antiga com `WHERE`

Antes da sintaxe de `JOIN ... ON` se consolidar no padrão SQL, era comum listar as tabelas separadas por vírgula no `FROM` e colocar a relação no `WHERE`:

```sql
SELECT
    Produto.NomeProduto,
    Fornecedor.NomeFornecedor
FROM Produto, Fornecedor
WHERE Produto.Fornecedor = Fornecedor.CodigoFornecedor;
```

Para esse caso de junção interna, o resultado pode ser equivalente a:

```sql
SELECT
    Produto.NomeProduto,
    Fornecedor.NomeFornecedor
FROM Produto
INNER JOIN Fornecedor
    ON Produto.Fornecedor = Fornecedor.CodigoFornecedor;
```

A forma com `JOIN ... ON` costuma ser mais clara porque separa a **condição de relacionamento** das demais condições de filtro.

## 5. `INNER JOIN`: somente linhas com correspondência

`INNER JOIN` retorna apenas combinações em que a condição do `ON` encontra correspondência nas duas tabelas.

A palavra `INNER` pode ser omitida:

```sql
FROM Produto
JOIN Fornecedor
    ON Produto.Fornecedor = Fornecedor.CodigoFornecedor
```

equivale a:

```sql
FROM Produto
INNER JOIN Fornecedor
    ON Produto.Fornecedor = Fornecedor.CodigoFornecedor
```

Para visualizar o comportamento dos diferentes tipos de `JOIN`, considere este exemplo didático.

### Tabela `Categoria`

| Codigo | Nome |
| --- | --- |
| C1 | Computadores |
| C2 | Impressoras |
| C3 | Acessórios |
| C4 | Suprimentos |

### Tabela `Produto`

| NomeProduto | Categoria |
| --- | --- |
| Computador AMD | C1 |
| Computador Intel | C1 |
| Impressora Epson | C2 |
| Mouse | C3 |
| Mesa digitalizadora | C3 |
| HD externo 1 TB | `NULL` |

A consulta:

```sql
SELECT
    Categoria.Nome AS Categoria,
    Produto.NomeProduto AS Produto
FROM Categoria
INNER JOIN Produto
    ON Produto.Categoria = Categoria.Codigo;
```

retorna somente as cinco linhas que possuem correspondência:

| Categoria | Produto |
| --- | --- |
| Computadores | Computador AMD |
| Computadores | Computador Intel |
| Impressoras | Impressora Epson |
| Acessórios | Mouse |
| Acessórios | Mesa digitalizadora |

`Suprimentos` não aparece porque não possui produto correspondente. O HD externo também não aparece porque não possui categoria associada.

## 6. `LEFT JOIN`: preservar todas as linhas da esquerda

`LEFT JOIN` mantém as linhas que possuem correspondência e **todas as linhas da tabela escrita à esquerda do `JOIN`**, mesmo quando não existe correspondente à direita.

```sql
SELECT
    Categoria.Nome AS Categoria,
    Produto.NomeProduto AS Produto
FROM Categoria
LEFT JOIN Produto
    ON Produto.Categoria = Categoria.Codigo;
```

Resultado:

| Categoria | Produto |
| --- | --- |
| Computadores | Computador AMD |
| Computadores | Computador Intel |
| Impressoras | Impressora Epson |
| Acessórios | Mouse |
| Acessórios | Mesa digitalizadora |
| Suprimentos | `NULL` |

`Suprimentos` aparece porque `Categoria` está à esquerda. Como não há produto correspondente, as colunas vindas de `Produto` ficam `NULL`.

O modelo mental é:

> **`LEFT JOIN` = tudo da esquerda + correspondências da direita.**

## 7. `RIGHT JOIN`: preservar todas as linhas da direita

`RIGHT JOIN` faz o inverso: mantém todas as linhas da tabela que aparece à direita.

```sql
SELECT
    Categoria.Nome AS Categoria,
    Produto.NomeProduto AS Produto
FROM Categoria
RIGHT JOIN Produto
    ON Produto.Categoria = Categoria.Codigo;
```

Resultado:

| Categoria | Produto |
| --- | --- |
| Computadores | Computador AMD |
| Computadores | Computador Intel |
| Impressoras | Impressora Epson |
| Acessórios | Mouse |
| Acessórios | Mesa digitalizadora |
| `NULL` | HD externo 1 TB |

O HD externo aparece porque `Produto` está à direita e sua linha é preservada mesmo sem categoria correspondente.

O modelo mental é:

> **`RIGHT JOIN` = tudo da direita + correspondências da esquerda.**

## 8. `FULL OUTER JOIN`: preservar os dois lados

`FULL OUTER JOIN`, também escrito como `FULL JOIN` em SGBDs que oferecem essa sintaxe, mantém linhas correspondentes e linhas sem correspondência de ambos os lados.

No exemplo:

| Categoria | Produto |
| --- | --- |
| Computadores | Computador AMD |
| Computadores | Computador Intel |
| Impressoras | Impressora Epson |
| Acessórios | Mouse |
| Acessórios | Mesa digitalizadora |
| Suprimentos | `NULL` |
| `NULL` | HD externo 1 TB |

A consulta conceitual é:

```sql
SELECT
    Categoria.Nome AS Categoria,
    Produto.NomeProduto AS Produto
FROM Categoria
FULL OUTER JOIN Produto
    ON Produto.Categoria = Categoria.Codigo;
```

> **Diferença entre SGBDs:** MySQL não implementa diretamente `FULL OUTER JOIN`. Uma alternativa estudada é combinar `LEFT JOIN` e `RIGHT JOIN` com `UNION`, apresentada mais adiante.

## 9. Comparando os principais tipos de `JOIN`

| Tipo | Regra de preservação |
| --- | --- |
| `INNER JOIN` | somente linhas com correspondência |
| `LEFT JOIN` | correspondências + todas as linhas da esquerda |
| `RIGHT JOIN` | correspondências + todas as linhas da direita |
| `FULL OUTER JOIN` | correspondências + linhas não correspondentes dos dois lados |

> **Precisão conceitual:** a teoria dos conjuntos ajuda a formar o modelo mental de interseção, união e diferença, mas `JOIN` combina **linhas e colunas segundo uma condição**. Um `LEFT JOIN`, por exemplo, não é literalmente o operador de diferença entre conjuntos; ele preserva também as linhas correspondentes.

## 10. Alias de tabela

Quando várias tabelas aparecem na mesma consulta, repetir nomes completos torna o código mais longo.

Podemos criar aliases:

```sql
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
JOIN Produto AS P
    ON P.Categoria = C.Codigo;
```

Aqui, `C` é o alias de `Categoria` e `P` é o alias de `Produto`. Depois que o alias é introduzido, ele pode qualificar as colunas, deixando claro de qual tabela cada atributo vem.

Isso é especialmente útil quando duas tabelas possuem colunas com o mesmo nome, como `Codigo`, `Nome` ou `DataCadastro`.

> O alias de tabela é temporário e vale apenas dentro daquela consulta, assim como o alias de coluna estudado em [[08. Funções agregadas e cálculos em SQL#3. Alias: dar um nome mais claro ao resultado|aliases de colunas]].

## 11. `CROSS JOIN`: produto cartesiano

Se duas tabelas forem combinadas sem uma relação que limite as correspondências, pode surgir um **produto cartesiano**: cada linha da primeira tabela é combinada com cada linha da segunda.

### Tabela T1

| Valor |
| --- |
| A |
| B |

### Tabela T2

| Valor |
| --- |
| 1 |
| 2 |
| 3 |

A consulta explícita:

```sql
SELECT T1.Valor, T2.Valor
FROM T1
CROSS JOIN T2;
```

produz:

| T1 | T2 |
| --- | --- |
| A | 1 |
| A | 2 |
| A | 3 |
| B | 1 |
| B | 2 |
| B | 3 |

Há 2 linhas em T1 e 3 em T2: `2 × 3 = 6 combinações`.

Esse comportamento explica um erro clássico. Se `Categoria` possui 4 linhas e `Produto` possui 6 e as tabelas são combinadas sem uma condição de relacionamento, o resultado pode ter `4 × 6 = 24 linhas`.

O produto cartesiano pode ser desejado em situações específicas, mas também pode criar resultados enormes. Por isso, quando ele aparece sem intenção, vale verificar se faltou uma condição de junção.

## 12. `JOIN` e teoria dos conjuntos

Algumas ideias da teoria dos conjuntos ajudam a organizar o raciocínio:

| Ideia | Pergunta mental | Recurso SQL relacionado |
| --- | --- | --- |
| Interseção | o que possui correspondência nos dois lados? | `INNER JOIN` |
| Preservação do lado esquerdo | quero os correspondentes e também o que existe somente à esquerda? | `LEFT JOIN` |
| Preservação do lado direito | quero os correspondentes e também o que existe somente à direita? | `RIGHT JOIN` |
| Preservação dos dois lados | quero correspondentes e não correspondentes dos dois lados? | `FULL OUTER JOIN` |
| União de resultados | quero empilhar linhas produzidas por consultas compatíveis? | `UNION` / `UNION ALL` |

A última linha é importante: **`UNION` não é um tipo de `JOIN`**. Ele combina resultados de consultas em outra direção.

## 13. `JOIN` combina colunas; `UNION` combina linhas

| Operação | O que faz? | Modelo visual |
| --- | --- | --- |
| `JOIN` | aproxima dados de tabelas relacionadas | coloca informações lado a lado |
| `UNION` | combina resultados compatíveis | empilha linhas uma abaixo da outra |

Com `JOIN`:

| Produto | Fornecedor |
| --- | --- |
| Mouse | Fornecedor Alfa |

Com `UNION`:

| Nome |
| --- |
| Categoria A |
| Categoria B |
| Produto X |
| Produto Y |

## 14. `UNION`: unir resultados removendo duplicidades

`UNION` combina o resultado de dois ou mais `SELECT`.

```sql
SELECT coluna1
FROM TabelaA

UNION

SELECT coluna2
FROM TabelaB;
```

Os `SELECT` precisam produzir o mesmo número de colunas em posições compatíveis.

Considere:

### Resultado A

| Valor |
| --- |
| 1 |
| 2 |

### Resultado B

| Valor |
| --- |
| 2 |
| 3 |

Com:

```sql
SELECT Valor FROM A
UNION
SELECT Valor FROM B;
```

o resultado é:

| Valor |
| --- |
| 1 |
| 2 |
| 3 |

O valor `2` aparece apenas uma vez porque `UNION` elimina linhas duplicadas do resultado combinado.

## 15. `UNION ALL`: unir resultados preservando duplicidades

Com os mesmos conjuntos:

```sql
SELECT Valor FROM A
UNION ALL
SELECT Valor FROM B;
```

o resultado é:

| Valor |
| --- |
| 1 |
| 2 |
| 2 |
| 3 |

O modelo mental é:

> **`UNION` remove duplicidades; `UNION ALL` preserva duplicidades.**

## 16. Simulando `FULL OUTER JOIN` no MySQL

Como MySQL não oferece `FULL OUTER JOIN` diretamente, uma estratégia possível é combinar um `LEFT JOIN` com um `RIGHT JOIN`.

```sql
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
LEFT JOIN Produto AS P
    ON P.Categoria = C.Codigo

UNION

SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
RIGHT JOIN Produto AS P
    ON P.Categoria = C.Codigo;
```

O uso de `UNION`, e não `UNION ALL`, evita repetir as linhas correspondentes que aparecem nos dois `SELECT`.

## 17. `ORDER BY` em consultas com `UNION`

Quando `ORDER BY` é aplicado ao resultado de um `UNION`, ele organiza o **resultado combinado**, e não apenas o segundo `SELECT`.

```sql
SELECT C.Nome AS Nome
FROM Categoria AS C

UNION

SELECT P.NomeProduto AS Nome
FROM Produto AS P

ORDER BY Nome;
```

Depois do `UNION`, a ordenação considera a coluna resultante `Nome`. Por isso, um qualificador como `P.NomeProduto` pertence a um dos `SELECT` de origem, mas não representa a coluna da tabela temporária produzida pelo resultado global.

## 18. `DISTINCT`: eliminar repetições dentro de um `SELECT`

Às vezes as duplicidades não vêm de um `UNION`, mas da própria consulta.

```sql
SELECT C.Nome
FROM Categoria AS C
JOIN Produto AS P
    ON P.Categoria = C.Codigo;
```

Como vários produtos podem pertencer à mesma categoria, nomes como `Computadores` e `Acessórios` podem aparecer mais de uma vez.

Para obter apenas valores distintos:

```sql
SELECT DISTINCT C.Nome
FROM Categoria AS C
JOIN Produto AS P
    ON P.Categoria = C.Codigo;
```

| Recurso | Onde atua sobre duplicidades? |
| --- | --- |
| `DISTINCT` | dentro do resultado de um `SELECT` |
| `UNION` | ao combinar resultados de diferentes `SELECT` |
| `UNION ALL` | não elimina duplicidades |

## 19. Script de prática

```sql
-- INNER JOIN
SELECT
    P.NomeProduto AS Produto,
    F.NomeFornecedor AS Fornecedor
FROM Produto AS P
INNER JOIN Fornecedor AS F
    ON P.Fornecedor = F.CodigoFornecedor;

-- JOIN equivale a INNER JOIN neste uso
SELECT
    P.NomeProduto AS Produto,
    F.NomeFornecedor AS Fornecedor
FROM Produto AS P
JOIN Fornecedor AS F
    ON P.Fornecedor = F.CodigoFornecedor;

-- LEFT JOIN
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
LEFT JOIN Produto AS P
    ON P.Categoria = C.Codigo;

-- RIGHT JOIN
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
RIGHT JOIN Produto AS P
    ON P.Categoria = C.Codigo;

-- CROSS JOIN
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
CROSS JOIN Produto AS P;

-- UNION
SELECT C.Nome AS Nome
FROM Categoria AS C
UNION
SELECT P.NomeProduto AS Nome
FROM Produto AS P;

-- UNION ALL
SELECT C.Nome AS Nome
FROM Categoria AS C
UNION ALL
SELECT P.NomeProduto AS Nome
FROM Produto AS P;

-- DISTINCT
SELECT DISTINCT C.Nome AS Categoria
FROM Categoria AS C
JOIN Produto AS P
    ON P.Categoria = C.Codigo;

-- FULL OUTER JOIN simulado no MySQL
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
LEFT JOIN Produto AS P
    ON P.Categoria = C.Codigo
UNION
SELECT
    C.Nome AS Categoria,
    P.NomeProduto AS Produto
FROM Categoria AS C
RIGHT JOIN Produto AS P
    ON P.Categoria = C.Codigo;
```

## Pontos que costumam gerar confusão

- **`JOIN` não significa simplesmente “colocar duas tabelas juntas”.** A condição em `ON` define quais linhas correspondem.
- **`INNER JOIN` e `JOIN` são equivalentes nos exemplos estudados.**
- **A ordem importa em `LEFT JOIN` e `RIGHT JOIN`.** “Esquerda” e “direita” se referem à posição das tabelas no `FROM`, não à ordem das colunas no `SELECT`.
- **Linhas sem correspondência aparecem com `NULL` no lado ausente em junções externas.**
- **`CROSS JOIN` produz produto cartesiano.** Com 4 linhas de um lado e 6 do outro, podem surgir 24 combinações.
- **`JOIN` e `UNION` fazem coisas diferentes.** `JOIN` combina colunas de linhas relacionadas; `UNION` empilha linhas de resultados compatíveis.
- **`UNION` e `UNION ALL` não são equivalentes.** O primeiro elimina duplicidades; o segundo preserva todas as linhas.
- **`DISTINCT` atua dentro de um `SELECT`.** Ele elimina repetições no resultado produzido por essa consulta.
- **MySQL não implementa `FULL OUTER JOIN` diretamente.** Uma alternativa é combinar `LEFT JOIN` e `RIGHT JOIN` com `UNION`.
- **Alias de tabela não renomeia a tabela no banco.** É apenas um nome temporário dentro da consulta.
