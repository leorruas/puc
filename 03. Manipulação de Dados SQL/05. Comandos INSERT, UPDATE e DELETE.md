# Comandos `INSERT`, `UPDATE` e `DELETE`

> **Contexto:** Depois de criar e alterar a estrutura das tabelas com comandos DDL, o próximo passo é manipular os dados armazenados nelas. Este artigo apresenta `INSERT`, `UPDATE` e `DELETE`, mostrando como inserir, alterar e excluir linhas com segurança e conectando essas operações a conceitos já estudados, como tipos de dados, chave primária, `NULL`, `NOT NULL` e `DEFAULT`.

As operações cotidianas de um banco de dados envolvem principalmente três ações: **incluir**, **alterar** e **excluir dados**. Em SQL, essas ações são realizadas por `INSERT`, `UPDATE` e `DELETE`.

Esses comandos atuam sobre os **dados armazenados nas linhas**, e não sobre a definição da tabela. Essa é a diferença central em relação aos comandos estudados anteriormente: `CREATE TABLE`, `ALTER TABLE` e `DROP TABLE` trabalham com a estrutura; `INSERT`, `UPDATE` e `DELETE` trabalham com o conteúdo.

## Da estrutura para os dados

Considere a tabela usada nos artigos anteriores:

```sql
CREATE TABLE Fornecedor (
    Codigo CHAR(3) PRIMARY KEY,
    Nome VARCHAR(100)
);
```

Enquanto ela estiver vazia, existe apenas sua estrutura: duas colunas, seus tipos e a restrição de chave primária. Para começar a usá-la, precisamos inserir linhas.

Inserir dados em uma tabela também é chamado de **popular a tabela**.

## `INSERT`: inserir novas linhas

A forma mais explícita de `INSERT` é:

```sql
INSERT INTO nome_da_tabela (coluna1, coluna2)
VALUES (valor1, valor2);
```

No exemplo de `Fornecedor`:

```sql
INSERT INTO Fornecedor (Codigo, Nome)
VALUES ('001', 'Fornecedor 1');
```

A leitura pode ser feita como uma frase:

- `INSERT INTO Fornecedor`: inserir na tabela `Fornecedor`;
- `(Codigo, Nome)`: preencher essas colunas, nessa ordem;
- `VALUES`: os valores que serão fornecidos vêm a seguir;
- `('001', 'Fornecedor 1')`: os valores correspondentes às colunas informadas.

### Valores textuais usam aspas simples

`Codigo` foi definido como `CHAR(3)`. Por isso, o valor `001` deve ser tratado como texto:

```sql
'001'
```

As aspas simples indicam uma cadeia de caracteres. Sem elas, `001` seria interpretado como um valor numérico.

O mesmo vale para o nome:

```sql
'Fornecedor 1'
```

## A ordem dos valores importa

É possível inserir valores sem listar explicitamente as colunas:

```sql
INSERT INTO Fornecedor
VALUES ('001', 'Fornecedor 1');
```

Nesse caso, os valores precisam corresponder à ordem das colunas esperada pelo comando e à estrutura considerada para a inserção.

Uma forma mais segura e legível é informar os nomes das colunas:

```sql
INSERT INTO Fornecedor (Codigo, Nome)
VALUES ('001', 'Fornecedor 1');
```

Ao explicitar as colunas, podemos inclusive mudar a ordem:

```sql
INSERT INTO Fornecedor (Nome, Codigo)
VALUES ('Fornecedor 2', '002');
```

A estrutura da tabela não muda. Apenas informamos que, naquele `INSERT`, o primeiro valor corresponde a `Nome` e o segundo a `Codigo`.

Por isso, a forma com lista de colunas costuma ser preferível: ela deixa a intenção explícita e reduz erros quando a estrutura da tabela evolui.

## É possível omitir algumas colunas?

Sim, desde que a definição da tabela permita isso.

Suponha:

```sql
INSERT INTO Fornecedor (Codigo)
VALUES ('004');
```

A coluna `Nome` não foi informada. O que acontece depende da definição dessa coluna.

### Quando a coluna aceita `NULL`

Se `Nome` aceitar `NULL`, a linha pode ser inserida:

| Codigo | Nome |
| --- | --- |
| 004 | `NULL` |

`NULL` significa **ausência de valor**. Não é uma string vazia, não é um espaço e não é o número zero.

Compare:

| Valor | Significado |
| --- | --- |
| `NULL` | ausência de valor |
| `''` | texto vazio |
| `' '` | um caractere de espaço |
| `0` | número zero |

### Quando existe um `DEFAULT`

Se uma coluna possuir um valor padrão, o SGBD pode utilizar esse valor quando a coluna não for informada no `INSERT`.

Por exemplo:

```sql
CREATE TABLE Exemplo (
    Codigo INT PRIMARY KEY,
    Ativo BOOLEAN NOT NULL DEFAULT TRUE
);
```

Então:

```sql
INSERT INTO Exemplo (Codigo)
VALUES (1);
```

faz com que `Ativo` receba seu valor padrão.

### Quando a coluna é `NOT NULL` e não possui valor padrão

Se a coluna é obrigatória e nenhum valor válido puder ser atribuído, a inserção não pode satisfazer a definição da tabela.

É o caso típico de uma chave primária:

```sql
INSERT INTO Fornecedor (Nome)
VALUES ('Fornecedor 3');
```

Se `Codigo` é a `PRIMARY KEY` e não possui geração automática de valor, o comando não fornece uma identificação válida para a nova linha e a inserção falha.

> **Precisão conceitual:** nesse exemplo, a obrigatoriedade decorre da **chave primária**, não de uma chave estrangeira. Uma `PRIMARY KEY` identifica unicamente cada linha e não admite `NULL`. Uma `FOREIGN KEY` possui outra função: representar uma referência entre tabelas e pode ou não admitir `NULL`, conforme sua própria definição.

## Inserindo várias linhas

No MySQL, é possível inserir várias linhas em uma única instrução:

```sql
INSERT INTO Fornecedor (Codigo, Nome)
VALUES
    ('001', 'Fornecedor 1'),
    ('002', 'Fornecedor 2'),
    ('003', 'Fornecedor 3');
```

A lista de colunas é declarada uma vez e cada par de parênteses depois de `VALUES` representa uma nova linha.

A portabilidade desse tipo de construção deve ser verificada quando se trabalha com outros SGBDs. Neste artigo, o exemplo corresponde ao comportamento apresentado com MySQL.

## Conferindo o resultado com `SELECT`

Aqui, `SELECT` é usado apenas para conferir se as operações deram certo:

```sql
SELECT *
FROM Fornecedor;
```

O asterisco significa que queremos visualizar todas as colunas da relação retornada.

O comando é aprofundado em [[06. Comando SELECT|06. Comando SELECT]]. Neste artigo, ele aparece apenas como ferramenta de inspeção para observar o resultado de `INSERT`, `UPDATE` e `DELETE`.

## `UPDATE`: alterar dados existentes

Depois que uma linha foi inserida, seus valores podem mudar. Um fornecedor pode trocar de nome, um cliente pode mudar de endereço e um saldo pode ser atualizado.

A estrutura básica é:

```sql
UPDATE nome_da_tabela
SET coluna = novo_valor
WHERE condição;
```

Suponha que a linha de código `004` tenha sido inserida sem nome. Podemos preenchê-lo assim:

```sql
UPDATE Fornecedor
SET Nome = 'Fornecedor 4'
WHERE Codigo = '004';
```

A leitura é:

- `UPDATE Fornecedor`: alterar dados da tabela `Fornecedor`;
- `SET Nome = 'Fornecedor 4'`: atribuir um novo valor à coluna `Nome`;
- `WHERE Codigo = '004'`: fazer isso apenas nas linhas que satisfazem essa condição.

## O perigo de `UPDATE` sem `WHERE`

Considere:

```sql
UPDATE Fornecedor
SET Nome = 'Fornecedor 4';
```

Sem `WHERE`, não existe uma condição restringindo quais linhas devem ser atualizadas. Portanto, o comando pode alterar **todas as linhas da tabela**.

Se a intenção é modificar somente o fornecedor `004`, precisamos delimitar a operação:

```sql
UPDATE Fornecedor
SET Nome = 'Fornecedor 4'
WHERE Codigo = '004';
```

Esse é um modelo mental importante:

> **`SET` diz o que mudar; `WHERE` diz em quais linhas mudar.**

Antes de executar um `UPDATE`, especialmente em banco real, é útil verificar mentalmente se a condição seleciona exatamente as linhas desejadas.

## `DELETE`: excluir linhas

`DELETE` remove linhas existentes de uma tabela.

Sua estrutura é:

```sql
DELETE FROM nome_da_tabela
WHERE condição;
```

Por exemplo:

```sql
DELETE FROM Fornecedor
WHERE Codigo = '003';
```

Apenas a linha cujo código é `003` será removida.

Assim como em `UPDATE`, a cláusula `WHERE` determina quais linhas serão afetadas.

## O perigo de `DELETE` sem `WHERE`

Considere:

```sql
DELETE FROM Fornecedor;
```

Sem `WHERE`, todas as linhas da tabela são alvo da exclusão.

Depois disso, a tabela fica vazia, mas **continua existindo** com suas colunas, tipos, chaves e restrições.

> **Precisão conceitual:** `DELETE FROM Produto;` não apaga a tabela. Ele apaga todas as **linhas** da tabela. Para remover a própria estrutura, usaríamos `DROP TABLE Produto;`, como estudado no [[04. Alteração e remoção de tabelas#`DROP TABLE`|artigo 04]].

Essa distinção também ajuda a lembrar a diferença entre três comandos:

| Comando | O que desaparece? | A estrutura permanece? |
| --- | --- | --- |
| `DELETE FROM tabela;` | Linhas | Sim |
| `TRUNCATE TABLE tabela;` | Todas as linhas | Sim |
| `DROP TABLE tabela;` | Linhas + tabela | Não |

`DELETE` e `TRUNCATE` podem deixar uma tabela vazia, mas são operações conceitualmente diferentes e possuem comportamentos diferentes em aspectos como filtragem, transações e mecanismos internos do SGBD. O uso de `COMMIT` e `ROLLBACK` para confirmar ou desfazer alterações é aprofundado em [[12. Transações em banco de dados, COMMIT e ROLLBACK|12. Transações em banco de dados, COMMIT e ROLLBACK]].

## Mensagens de erro fazem parte do aprendizado

Ao executar uma instrução, o SGBD pode rejeitá-la quando os valores não correspondem à estrutura definida.

Alguns exemplos de problemas que podem aparecer são:

- valor maior do que o tamanho permitido;
- ordem dos valores incompatível com as colunas;
- ausência de valor para uma coluna obrigatória;
- tentativa de inserir valor incompatível com o tipo;
- violação de chave primária ou outra restrição.

Em vez de tratar a mensagem de erro apenas como um obstáculo, vale lê-la como uma descrição da regra do banco que foi violada.

Isso conecta diretamente este artigo ao anterior: a estrutura criada por `CREATE TABLE` e modificada por `ALTER TABLE` determina quais operações de manipulação serão aceitas.

## Script completo comentado

O exemplo abaixo reúne os três comandos principais usando a tabela `Fornecedor`:

```sql
-- seleciona o banco criado nos exemplos anteriores
USE ComercioTI;


-- =========================================================
-- 1. PREPARA A TABELA PARA O EXEMPLO
-- =========================================================

DROP TABLE IF EXISTS Fornecedor;

CREATE TABLE Fornecedor (
    Codigo CHAR(3) PRIMARY KEY,
    Nome VARCHAR(100)
);


-- =========================================================
-- 2. INSERT: INSERE AS PRIMEIRAS LINHAS
-- =========================================================

INSERT INTO Fornecedor (Codigo, Nome)
VALUES ('001', 'Fornecedor 1');

-- a ordem pode mudar quando os nomes das colunas são informados
INSERT INTO Fornecedor (Nome, Codigo)
VALUES ('Fornecedor 2', '002');

-- também podemos inserir várias linhas em uma instrução no MySQL
INSERT INTO Fornecedor (Codigo, Nome)
VALUES
    ('003', 'Fornecedor 3'),
    ('004', NULL);

-- confere o estado atual
SELECT *
FROM Fornecedor;


-- =========================================================
-- 3. UPDATE: CORRIGE O NOME DO FORNECEDOR 004
-- =========================================================

UPDATE Fornecedor
SET Nome = 'Fornecedor 4'
WHERE Codigo = '004';

SELECT *
FROM Fornecedor;


-- =========================================================
-- 4. DELETE: REMOVE SOMENTE O FORNECEDOR 003
-- =========================================================

DELETE FROM Fornecedor
WHERE Codigo = '003';

SELECT *
FROM Fornecedor;


-- =========================================================
-- 5. EXEMPLOS PERIGOSOS: NÃO EXECUTAR SEM QUERER
-- =========================================================

-- sem WHERE, este comando mudaria o Nome de todas as linhas:
-- UPDATE Fornecedor
-- SET Nome = 'Mesmo nome para todos';

-- sem WHERE, este comando removeria todas as linhas:
-- DELETE FROM Fornecedor;
```

O script deixa visível a sequência completa: **criar estrutura → inserir linhas → consultar → alterar uma linha → consultar → excluir uma linha → consultar**.

## Pontos que costumam gerar confusão

- **`INSERT` atua sobre linhas, não sobre a estrutura da tabela.** A estrutura já precisa existir para que os dados sejam inseridos.
- **Listar explicitamente as colunas torna o `INSERT` mais claro e seguro.** Também permite alterar a ordem dos valores ou omitir colunas opcionais.
- **`NULL` não é espaço, string vazia nem zero.** Ele representa ausência de valor.
- **Uma `PRIMARY KEY` não pode ser `NULL`.** Essa obrigatoriedade decorre da chave primária; uma `FOREIGN KEY` tem outra função e sua nulabilidade depende da definição da coluna.
- **`DEFAULT` fornece um valor padrão quando a definição da coluna e a instrução permitem utilizá-lo.**
- **`SET` indica o novo valor; `WHERE` delimita quais linhas serão atualizadas.**
- **`UPDATE` sem `WHERE` pode alterar todas as linhas.**
- **`DELETE` sem `WHERE` pode remover todas as linhas, mas não remove a tabela.**
- **`DELETE`, `TRUNCATE` e `DROP` não são sinônimos.** Os dois primeiros preservam a estrutura; `DROP` remove a própria tabela.
- **Mensagens de erro revelam conflitos entre os dados fornecidos e as regras do esquema.**
