# Manipulação de dados com SQL

## Visão geral

A disciplina estuda SQL como linguagem de interação com bancos de dados relacionais. Até agora, o conteúdo cobre os fundamentos da linguagem, sua relação com o modelo relacional, o funcionamento de SGBDs e ferramentas clientes, a DDL para criação e alteração de estruturas, a DML com inserção, atualização e exclusão de linhas e consultas com `SELECT`, filtros, operadores, predicados, ordenação, funções agregadas, agrupamento de resultados e combinação de dados entre tabelas com `JOIN` e entre resultados com `UNION`.

O percurso se conecta diretamente a [[02. Modelagem de Dados/00. Modelagem de Dados - Resumo|Modelagem de dados]]: aquilo que antes era representado como entidade, atributo, identificador, relacionamento e cardinalidade passa a ser implementado no SGBD como tabela, coluna, chave e restrição.

## Pontos centrais até agora

SQL é uma linguagem, não um banco de dados nem um SGBD. Ela permite expressar operações sobre estruturas relacionais, enquanto o SGBD decide como executar essas operações e administrar os dados.

A linguagem é declarativa porque descreve principalmente **o que** se deseja obter ou realizar, deixando para o SGBD a escolha de **como** executar a operação. Também é de alto nível porque abstrai detalhes físicos de armazenamento e processamento.

DDL, DML, DQL e DCL organizam as instruções conforme sua finalidade. `CREATE TABLE` cria estruturas; `ALTER TABLE` modifica sua definição; `DROP TABLE` elimina a tabela; e `TRUNCATE TABLE` remove todas as linhas preservando a estrutura. Já comandos como `INSERT`, `UPDATE` e `DELETE` atuam sobre os dados, enquanto `SELECT` realiza consultas e pode aparecer classificado como DQL ou DML conforme a referência.

Funções agregadas permitem resumir conjuntos de dados em valores como média, quantidade, máximo, mínimo e soma. `COUNT(*)` conta linhas, enquanto `COUNT(coluna)` conta apenas valores não nulos daquela coluna; `AVG`, `MAX`, `MIN` e `SUM` também desconsideram `NULL` nos cálculos apresentados.

`GROUP BY` permite calcular essas agregações separadamente para grupos definidos por uma coluna, como quantidade de fornecedores por estado ou média de preços por categoria. `HAVING` filtra os grupos segundo condições aplicadas aos resultados agregados, enquanto `WHERE` continua restringindo as linhas consideradas pela consulta.

`JOIN` permite combinar dados de tabelas relacionadas, normalmente ligando uma chave estrangeira à chave primária correspondente. `INNER JOIN` mantém apenas correspondências; `LEFT JOIN` e `RIGHT JOIN` preservam um dos lados; `FULL OUTER JOIN` preserva ambos quando o SGBD oferece o recurso; e `CROSS JOIN` produz o produto cartesiano. `UNION` e `UNION ALL` trabalham de outra forma: empilham linhas de resultados compatíveis, removendo ou preservando duplicidades, respectivamente.

A estrutura relacional conecta diretamente esta disciplina a Modelagem de dados. Entidades tornam-se tabelas, atributos tornam-se colunas, identificadores tornam-se chaves primárias e relacionamentos serão implementados por chaves estrangeiras e restrições.

No modelo relacional, **domínio** significa o conjunto de valores válidos para um atributo. Esse sentido é diferente de **domínio da aplicação** em [[05. Desenvolvimento Web Back-End/01. Arquitetura de software e cliente-servidor#O que é domínio|Desenvolvimento Web Back-End]], onde domínio representa a área de problema, seus conceitos e regras.

MySQL, PostgreSQL e SQL Server implementam SQL, mas possuem diferenças de sintaxe, tipos e recursos. Por isso, é importante distinguir conceitos transferíveis da linguagem de extensões ou comportamentos específicos de cada SGBD.
