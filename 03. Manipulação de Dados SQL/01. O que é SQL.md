# O que é SQL

> **Contexto:** Este artigo introduz SQL como linguagem de comunicação com bancos de dados relacionais, explica por que ela é declarativa e de alto nível, organiza seus principais grupos de instruções e situa sua origem histórica, padronização e variações entre SGBDs. A leitura conecta diretamente SQL ao modelo relacional estudado em [[02. Modelagem de Dados/00. Modelagem de Dados - Resumo|Modelagem de dados]].

SQL é a sigla para **Structured Query Language**, ou linguagem de consulta estruturada. Ela foi criada para trabalhar com dados armazenados em bancos de dados relacionais e é implementada, com variações, pelos principais sistemas gerenciadores de bancos de dados relacionais, os SGBDs. Por meio de SQL, é possível consultar informações, inserir registros, alterar ou excluir dados existentes, definir estruturas do banco e controlar permissões de acesso.

Por isso, SQL aparece em diferentes áreas da computação. Desenvolvedores, analistas de sistemas, engenheiros de software, administradores de bancos de dados e profissionais de TI em geral usam a linguagem para interagir com estruturas relacionais. Ela também é central na área de dados, incluindo o trabalho de engenheiros de dados, analistas de dados e cientistas de dados. O ponto central, porém, não é decorar comandos: é entender que SQL fornece uma forma padronizada de expressar operações sobre dados organizados em relações.

## SQL como linguagem declarativa e de alto nível

SQL trabalha principalmente no **nível lógico dos dados**. Quem escreve uma instrução informa ao SGBD o resultado desejado ou a operação que deve ser realizada, sem precisar determinar cada passo físico usado para localizar, ordenar ou armazenar os dados.

Por isso, SQL é considerada uma **linguagem declarativa**. Considere uma tabela chamada `Cliente`. Para encontrar os clientes que vivem em Belo Horizonte, podemos escrever:

```sql
SELECT *
FROM Cliente
WHERE cidade = 'Belo Horizonte';
```

A consulta declara o que queremos obter: as linhas de `Cliente` cujo valor de `cidade` seja `Belo Horizonte`. Ela não manda o computador abrir determinado arquivo, percorrer registros em uma ordem específica ou comparar manualmente cada valor. O SGBD recebe a consulta e decide como executá-la, podendo, por exemplo, percorrer a tabela inteira ou aproveitar um índice existente. A estratégia escolhida pelo SGBD é chamada de **plano de execução**.

SQL também é considerada uma linguagem de **alto nível** porque oferece uma camada de abstração sobre detalhes físicos de armazenamento e processamento. Em vez de trabalhar diretamente com endereços de memória, páginas de disco ou algoritmos internos de busca, o usuário trabalha com conceitos como tabelas, colunas, relações e conjuntos de dados.

### Uma analogia para linguagem declarativa

Uma forma simples de visualizar essa diferença é pensar em um pedido de restaurante. Ao pedir um prato, você informa **o resultado desejado**, mas não descreve ao cozinheiro cada movimento necessário para prepará-lo. Em SQL ocorre algo semelhante: a consulta expressa o que queremos dos dados, enquanto o SGBD escolhe a estratégia para chegar ao resultado.

O termo **Structured** em *Structured Query Language* não significa que a linguagem seja de alto nível. O nome tem origem histórica em **SEQUEL, Structured English Query Language**, linguagem desenvolvida na IBM na década de 1970 e posteriormente renomeada como SQL.

## Principais grupos de instruções SQL

As instruções SQL podem ser agrupadas conforme sua função. Uma classificação didática comum utiliza DDL, DML e DCL; alguns materiais também separam consultas em uma categoria chamada DQL.

| Grupo   | Nome                         | Função principal                                                       | Comandos comuns              |
| ------- | ---------------------------- | ---------------------------------------------------------------------- | ---------------------------- |
| **DDL** | *Data Definition Language*   | Definir e modificar estruturas do banco                                | `CREATE`, `ALTER`, `DROP`    |
| **DML** | *Data Manipulation Language* | Inserir, alterar e remover dados                                       | `INSERT`, `UPDATE`, `DELETE` |
| **DQL** | *Data Query Language*        | Consultar dados, em classificações que separam consulta de manipulação | `SELECT`                     |
| **DCL** | *Data Control Language*      | Controlar permissões e privilégios                                     | `GRANT`, `REVOKE`            |

### DDL: definição da estrutura

A **Data Definition Language** reúne comandos usados para criar e modificar a estrutura do banco de dados, incluindo tabelas, colunas, visões e índices. Um exemplo simples é a criação de uma tabela:

```sql
CREATE TABLE Cliente (
    id INTEGER,
    nome VARCHAR(100)
);
```

Nesse caso, ainda não estamos cadastrando clientes. Estamos definindo uma estrutura capaz de armazená-los.

### DML e DQL: manipulação e consulta

A **Data Manipulation Language** reúne instruções que atuam sobre os dados existentes ou que serão inseridos. Um exemplo é:

```sql
INSERT INTO Cliente (id, nome)
VALUES (1, 'Ana');
```

Aqui a tabela já existe e estamos alterando seu conteúdo ao acrescentar uma nova linha. `UPDATE` modifica dados existentes e `DELETE` remove linhas.

A classificação de `SELECT` merece atenção. Algumas referências o tratam como parte da DML porque a consulta é uma operação sobre dados. Outras usam **DQL, Data Query Language**, como categoria específica para consultas. DQL é, portanto, uma classificação didática útil, mas não deve ser entendida como uma divisão universal adotada da mesma maneira por toda documentação de SQL.

### DCL: controle de acesso

A **Data Control Language** reúne instruções relacionadas a permissões e privilégios. `GRANT` concede determinado acesso e `REVOKE` o remove. Esses comandos permitem definir, por exemplo, quais usuários podem consultar ou modificar determinados objetos do banco.

## Origem, padronização e dialetos

SQL surgiu na década de 1970 a partir das pesquisas da IBM sobre bancos de dados relacionais. Donald D. Chamberlin e Raymond F. Boyce desenvolveram a linguagem inicialmente chamada **SEQUEL**, baseada no modelo relacional proposto por Edgar F. Codd. A linguagem foi usada no projeto **System R**, um dos primeiros sistemas experimentais importantes a implementar esse modelo.

A proposta tinha uma consequência prática importante: permitir que pessoas consultassem e manipulassem dados relacionais por meio de uma linguagem mais acessível do que as notações matemáticas empregadas na pesquisa inicial sobre bancos de dados. Com a difusão dos SGBDs relacionais, diferentes fornecedores passaram a implementar SQL em seus produtos.

A linguagem recebeu padronização formal pelo ANSI em 1986 e, posteriormente, pela ISO. Desde então, o padrão SQL passa por revisões e fornece uma base comum para diferentes SGBDs.

### SQL padrão, extensões e dialetos

O padrão não significa que todos os SGBDs ofereçam exatamente a mesma linguagem. PostgreSQL, MySQL, Oracle Database e Microsoft SQL Server implementam grande parte do SQL padronizado, mas também acrescentam funções, tipos de dados, comandos e formas de escrita próprias.

Esses recursos adicionais são chamados de **extensões**. Quando o conjunto de diferenças de um SGBD é considerado como uma variante da linguagem, também usamos a expressão **dialeto SQL**. Extensões podem facilitar tarefas ou disponibilizar recursos específicos, mas aumentam a dependência daquele SGBD e podem reduzir a portabilidade de uma consulta para outro sistema.

Neste microfundamento, o foco inicial é o **SQL padronizado pelo ANSI/ISO**, para que os conceitos aprendidos sejam transferíveis entre diferentes bancos relacionais. Quando uma sintaxe depender de um fornecedor específico, essa diferença deve ser tratada explicitamente.

## Ponte com o modelo relacional

SQL dá continuidade ao que foi estudado em [[02. Modelagem de Dados/00. Modelagem de Dados - Resumo|Modelagem de dados]]. A modelagem define como informações são organizadas em entidades, atributos, relacionamentos, chaves e restrições; o modelo relacional traduz essas decisões em relações; SQL fornece a linguagem usada para definir, consultar e modificar sua implementação em um SGBD.

A sequência mental pode ser resumida assim: **modelo conceitual → modelo relacional → implementação no SGBD → operações SQL**. A modelagem responde principalmente a “como os dados devem ser organizados?”, enquanto SQL permite responder “como criar essa estrutura e como consultar ou modificar os dados nela armazenados?”.

## Pontos que costumam gerar confusão

- **SQL é declarativa porque expressa o que se deseja obter ou realizar.** O nome *Structured* não é a causa dessa característica.
- **Alto nível significa abstração.** O usuário não precisa controlar diretamente detalhes físicos de armazenamento ou os algoritmos internos usados pelo SGBD.
- **DDL atua sobre a estrutura; DML atua sobre os dados.** `CREATE TABLE` define uma tabela; `INSERT` adiciona registros nela.
- **DQL não é uma classificação universal.** Alguns materiais separam `SELECT` em DQL; outros o incluem em DML.
- **Extensão e dialeto não significam outro banco de dados.** São diferenças de sintaxe ou recursos acrescentadas à base comum da linguagem SQL.
