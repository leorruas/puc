# Glossário de conceitos

Este glossário reúne os conceitos já efetivamente estudados em Manipulação de dados com SQL. As definições devem ser lidas junto aos artigos de origem, indicados por links para as seções específicas.

| Conceito | Definição | Distinção importante | Referência |
| --- | --- | --- | --- |
| **SQL** | Linguagem usada para definir, consultar, manipular e controlar dados em SGBDs relacionais. | SQL é uma linguagem, não um banco de dados nem um SGBD. | [[01. O que é SQL#1. SQL como linguagem declarativa e de alto nível\|Artigo 01]] |
| **Linguagem declarativa** | Linguagem em que o usuário expressa principalmente o resultado desejado, enquanto o sistema decide como executar a operação. | Em SQL, declarar o resultado não significa controlar o algoritmo físico de acesso aos dados. | [[01. O que é SQL#1. SQL como linguagem declarativa e de alto nível\|Artigo 01]] |
| **Linguagem de alto nível** | Linguagem que oferece abstrações sobre detalhes físicos de execução e armazenamento. | *Structured* no nome SQL não significa “alto nível”; são ideias diferentes. | [[01. O que é SQL#1. SQL como linguagem declarativa e de alto nível\|Artigo 01]] |
| **Plano de execução** | Estratégia escolhida pelo SGBD para executar uma instrução SQL. | A mesma consulta pode ter diferentes estratégias conforme índices, estatísticas e estrutura do banco. | [[01. O que é SQL#1. SQL como linguagem declarativa e de alto nível\|Artigo 01]] |
| **DDL** | *Data Definition Language*: grupo de instruções usado para criar ou alterar estruturas do banco. | Atua principalmente sobre estrutura, não sobre o conteúdo das linhas. | [[01. O que é SQL#2. Principais grupos de instruções SQL\|Artigo 01]] |
| **DML** | *Data Manipulation Language*: grupo de instruções usado para inserir, alterar ou remover dados. | Algumas classificações também incluem `SELECT` em DML. | [[01. O que é SQL#2. Principais grupos de instruções SQL\|Artigo 01]] |
| **DQL** | *Data Query Language*: classificação didática usada por algumas referências para instruções de consulta. | Não é uma divisão universal; `SELECT` também pode aparecer classificado como DML. | [[01. O que é SQL#2. Principais grupos de instruções SQL\|Artigo 01]] |
| **DCL** | *Data Control Language*: grupo de instruções voltado ao controle de permissões e privilégios. | `GRANT` concede privilégios e `REVOKE` os remove. | [[01. O que é SQL#2. Principais grupos de instruções SQL\|Artigo 01]] |
| **Extensão SQL** | Funcionalidade, sintaxe ou tipo acrescentado por um SGBD além da base padronizada. | Extensões podem reduzir a portabilidade entre SGBDs. | [[01. O que é SQL#SQL padrão, extensões e dialetos\|Artigo 01]] |
| **Dialeto SQL** | Variante de SQL formada pelas particularidades implementadas por determinado SGBD. | PostgreSQL, MySQL, Oracle Database e SQL Server compartilham a base SQL, mas possuem diferenças. | [[01. O que é SQL#SQL padrão, extensões e dialetos\|Artigo 01]] |
| **Relação** | Estrutura do modelo relacional normalmente representada como tabela. | Relação é o conceito formal; tabela é a representação prática mais comum. | [[02. Bancos de dados relacionais e SGBDs#1. Estrutura de um banco de dados relacional\|Artigo 02]] |
| **Tupla** | Linha de uma relação. | No uso cotidiano de ferramentas SQL, costuma ser chamada simplesmente de linha ou registro. | [[02. Bancos de dados relacionais e SGBDs#1. Estrutura de um banco de dados relacional\|Artigo 02]] |
| **Atributo** | Coluna de uma relação. | O atributo possui um domínio de valores possíveis. | [[02. Bancos de dados relacionais e SGBDs#1. Estrutura de um banco de dados relacional\|Artigo 02]] |
| **Domínio relacional** | Conjunto de valores válidos que um atributo pode assumir. | Não é o mesmo que domínio da aplicação em arquitetura de software. | [[02. Bancos de dados relacionais e SGBDs#Tipos de dados, domínios e restrições\|Artigo 02]] |
| **Domínio da aplicação** | Área de problema que o software representa, incluindo conceitos, regras e operações. | Em Web Back-End, domínio descreve o problema; no modelo relacional, domínio limita valores de atributos. | [[02. Bancos de dados relacionais e SGBDs#A palavra domínio muda de sentido em Web Back-End\|Artigo 02]] e [[05. Desenvolvimento Web Back-End/01. Arquitetura de software e cliente-servidor#O que é domínio\|Web Back-End, artigo 01]] |
| **Restrição** | Regra aplicada pelo SGBD para impedir estados inválidos. | Exemplos incluem `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE` e `CHECK`. | [[02. Bancos de dados relacionais e SGBDs#Integridade dos dados\|Artigo 02]] |
| **Integridade dos dados** | Propriedade de manter os dados coerentes com as regras definidas no banco. | O próprio SGBD pode rejeitar operações que violem restrições. | [[02. Bancos de dados relacionais e SGBDs#Integridade dos dados\|Artigo 02]] |
| **Chave primária** | Atributo ou conjunto de atributos que identifica unicamente uma linha. | Não deve haver duas linhas com a mesma identificação primária. | [[02. Bancos de dados relacionais e SGBDs#Chaves e relacionamentos\|Artigo 02]] |
| **Chave estrangeira** | Atributo ou conjunto de atributos que referencia uma chave de outra relação. | É um mecanismo central para representar relacionamentos entre tabelas. | [[02. Bancos de dados relacionais e SGBDs#Chaves e relacionamentos\|Artigo 02]] |
| **SGBD** | Sistema Gerenciador de Banco de Dados: software que administra bancos, conexões, consultas, estruturas, permissões e persistência. | SGBD não é sinônimo de banco de dados e também não é sinônimo de SQL. | [[02. Bancos de dados relacionais e SGBDs#2. Banco de dados, SGBD, servidor e cliente\|Artigo 02]] |
| **Servidor de banco de dados** | Processo do SGBD que recebe conexões e processa operações sobre os bancos. | Pode continuar ativo mesmo quando o cliente gráfico é fechado. | [[02. Bancos de dados relacionais e SGBDs#3. O SGBD como serviço do sistema operacional\|Artigo 02]] |
| **Cliente de banco de dados** | Programa ou aplicação que abre uma conexão e envia instruções ao SGBD. | DBeaver e o cliente `mysql` são clientes; não são o servidor. | [[02. Bancos de dados relacionais e SGBDs#Arquitetura cliente-servidor\|Artigo 02]] |
| **Driver de banco de dados** | Componente que permite a uma ferramenta cliente se comunicar com determinado SGBD. | DBeaver usa drivers diferentes conforme o banco escolhido. | [[02. Bancos de dados relacionais e SGBDs#DBeaver\|Artigo 02]] |
| **Metadados** | Dados que descrevem a estrutura de outros dados, como nomes de colunas, tipos, chaves e restrições. | Visualizar metadados não é o mesmo que visualizar as linhas armazenadas na tabela. | [[02. Bancos de dados relacionais e SGBDs#5. O que aparece ao explorar uma tabela\|Artigo 02]] |

| **`CREATE TABLE`** | Comando DDL usado para criar uma tabela e definir suas colunas, tipos e restrições. | Materializa no SGBD decisões tomadas na modelagem de dados. | [[03. Comando CREATE TABLE#2. Estrutura básica de `CREATE TABLE`\|Artigo 03]] |
| **`CHAR(n)`** | Tipo textual de comprimento fixo com `n` posições. | Um valor como `'123'` continua sendo texto, não número inteiro. | [[03. Comando CREATE TABLE#3. O que significa `CHAR`\|Artigo 03]] |
| **`VARCHAR(n)`** | Tipo textual de comprimento variável até um limite definido. | Difere de `CHAR`, que trabalha com comprimento fixo. | [[03. Comando CREATE TABLE#3. O que significa `CHAR`\|Artigo 03]] |
| **`CREATE DATABASE`** | Comando usado em SGBDs como MySQL e SQL Server para criar um banco de dados. | Não deve ser confundido com `CREATE TABLE`; sua disponibilidade e semântica podem variar entre SGBDs. | [[03. Comando CREATE TABLE#5. Criando e selecionando um banco de dados\|Artigo 03]] |
| **`USE`** | Comando que altera o banco corrente da sessão em SGBDs como MySQL e SQL Server. | Não é um mecanismo universal e idêntico em todos os SGBDs. | [[03. Comando CREATE TABLE#5. Criando e selecionando um banco de dados\|Artigo 03]] |
| **Schema no MySQL** | Nome alternativo para database no contexto dos comandos de criação e seleção do MySQL. | Em outros SGBDs, database e schema podem representar níveis distintos de organização. | [[03. Comando CREATE TABLE#Database e schema no MySQL\|Artigo 03]] |
| **Terminador de instrução** | Símbolo usado para marcar o final de uma instrução SQL, normalmente `;`. | O ponto e vírgula encerra a instrução completa, não cada linha de código. | [[03. Comando CREATE TABLE#7. O ponto e vírgula\|Artigo 03]] |

| **`ALTER TABLE`** | Comando DDL usado para modificar a definição de uma tabela existente. | A ação específica vem depois, como adicionar, alterar, renomear ou remover colunas. | [[04. Alteração e remoção de tabelas#2. `ALTER TABLE`\|Artigo 04]] |
| **`DROP TABLE`** | Comando que remove completamente uma tabela do banco. | Elimina tanto a estrutura quanto os dados armazenados nela. | [[04. Alteração e remoção de tabelas#3. `DROP TABLE`\|Artigo 04]] |
| **`TRUNCATE TABLE`** | Comando que remove todas as linhas de uma tabela preservando sua estrutura. | Não aceita `WHERE` e não deve ser confundido com `DROP TABLE`. | [[04. Alteração e remoção de tabelas#4. `TRUNCATE TABLE`\|Artigo 04]] |
| **`RENAME TABLE`** | Comando do MySQL usado para alterar o nome de uma tabela. | Não é sintaxe universal; outros SGBDs podem usar `ALTER TABLE ... RENAME TO` ou mecanismos próprios. | [[04. Alteração e remoção de tabelas#6. `RENAME TABLE`\|Artigo 04]] |
| **`DROP COLUMN`** | Operação de `ALTER TABLE` que remove uma coluna de uma tabela. | Também elimina os dados armazenados naquela coluna. | [[04. Alteração e remoção de tabelas#Remover uma coluna\|Artigo 04]] |
| **`TRUNCATE` versus `DELETE`** | Distinção entre esvaziar uma tabela inteira e remover linhas por uma operação de manipulação de dados. | `TRUNCATE` não aceita filtro; `DELETE` pode usar `WHERE`. | [[04. Alteração e remoção de tabelas#5. `TRUNCATE TABLE` versus `DELETE`\|Artigo 04]] |

| **`INSERT`** | Comando DML usado para inserir novas linhas em uma tabela. | A lista de colunas define a correspondência e a ordem dos valores fornecidos. | [[05. Comandos INSERT, UPDATE e DELETE#2. `INSERT`: inserir novas linhas\|Artigo 05]] |
| **`VALUES`** | Palavra-chave que introduz os valores de uma nova linha em um `INSERT`. | Os valores precisam corresponder às colunas informadas. | [[05. Comandos INSERT, UPDATE e DELETE#2. `INSERT`: inserir novas linhas\|Artigo 05]] |
| **`NULL`** | Marcador de ausência de valor. | Não é espaço, string vazia nem zero. | [[05. Comandos INSERT, UPDATE e DELETE#4. É possível omitir algumas colunas?\|Artigo 05]] |
| **`DEFAULT`** | Valor padrão definido para uma coluna quando nenhum outro valor é fornecido em situações permitidas. | Não substitui automaticamente qualquer dado ausente em todos os cenários; depende da definição da coluna e da instrução. | [[05. Comandos INSERT, UPDATE e DELETE#Quando existe um `DEFAULT`\|Artigo 05]] |
| **`UPDATE`** | Comando DML usado para alterar valores de linhas existentes. | Sem `WHERE`, pode afetar todas as linhas da tabela. | [[05. Comandos INSERT, UPDATE e DELETE#7. `UPDATE`: alterar dados existentes\|Artigo 05]] |
| **`SET`** | Parte do `UPDATE` que define o novo valor atribuído a uma coluna. | `SET` diz o que mudar; `WHERE` delimita onde mudar. | [[05. Comandos INSERT, UPDATE e DELETE#8. O perigo de `UPDATE` sem `WHERE`\|Artigo 05]] |
| **`WHERE`** | Cláusula que restringe quais linhas satisfazem uma condição em consultas e operações de manipulação. | Em `SELECT`, filtra as linhas retornadas; em `UPDATE` e `DELETE`, delimita as linhas afetadas. | [[06. Comando SELECT#6. `WHERE`: filtrar as linhas\|Artigo 06]] |
| **`DELETE`** | Comando DML usado para remover linhas de uma tabela. | `DELETE FROM tabela;` remove as linhas, mas mantém a estrutura da tabela. | [[05. Comandos INSERT, UPDATE e DELETE#9. `DELETE`: excluir linhas\|Artigo 05]] |
| **Query** | Consulta feita ao banco de dados para recuperar e apresentar informações. | Uma query pode selecionar colunas, filtrar linhas e ordenar o resultado. | [[06. Comando SELECT#1. Consulta ou query\|Artigo 06]] |
| **`SELECT`** | Comando usado para recuperar dados e definir quais colunas aparecem no resultado. | Consultar dados não significa alterá-los. | [[06. Comando SELECT#3. `SELECT`: escolher as colunas\|Artigo 06]] |
| **`SELECT *`** | Forma de selecionar todas as colunas disponíveis no resultado de uma consulta. | O asterisco se refere às colunas, não necessariamente a todas as linhas. | [[06. Comando SELECT#4. O asterisco `*`\|Artigo 06]] |
| **`FROM`** | Cláusula que identifica a origem dos dados da consulta. | Nesta etapa, a origem apresentada é uma tabela. | [[06. Comando SELECT#5. `FROM`: indicar a origem dos dados\|Artigo 06]] |
| **`ORDER BY`** | Cláusula que organiza as linhas retornadas por uma consulta segundo uma coluna. | Atua sobre a apresentação do resultado, não sobre a organização física da tabela. | [[06. Comando SELECT#7. `ORDER BY`: ordenar o resultado\|Artigo 06]] |
| **Operadores de comparação** | Operadores como `=`, `<>`, `>`, `<`, `>=` e `<=` usados para comparar valores em condições. | A presença de `=` em `>=` ou `<=` inclui o valor de referência no limite. | [[07. Operadores e condições em consultas SQL#1. Operadores de comparação\|Artigo 07]] |
| **`AND`** | Operador lógico que exige que todas as condições combinadas sejam satisfeitas. | Difere de `OR`, que admite alternativas. | [[07. Operadores e condições em consultas SQL#3. `AND`: todas as condições precisam ser verdadeiras\|Artigo 07]] |
| **`OR`** | Operador lógico que permite que a linha seja aceita quando pelo menos uma condição é satisfeita. | Não exige que todas as condições sejam verdadeiras. | [[07. Operadores e condições em consultas SQL#4. `OR`: basta uma condição ser verdadeira\|Artigo 07]] |
| **`BETWEEN`** | Predicado usado para verificar se um valor está dentro de um intervalo. | Nos exemplos estudados, inclui os limites inferior e superior. | [[07. Operadores e condições em consultas SQL#5. `BETWEEN`: filtrar por intervalo\|Artigo 07]] |
| **`IN`** | Predicado que verifica se um valor pertence a uma lista de valores. | Pode substituir várias comparações alternativas em casos apropriados. | [[07. Operadores e condições em consultas SQL#6. `IN`: comparar com uma lista de valores\|Artigo 07]] |
| **`NOT`** | Operador lógico de negação. | Pode inverter o sentido de uma condição, como em `NOT IN`. | [[07. Operadores e condições em consultas SQL#7. `NOT`: negar uma condição\|Artigo 07]] |
| **`IS NULL`** | Predicado que verifica ausência de valor. | `NULL` não é testado com igualdade nos casos estudados. | [[07. Operadores e condições em consultas SQL#8. `NULL` precisa de `IS NULL`\|Artigo 07]] |
| **`IS NOT NULL`** | Predicado que verifica se há um valor não nulo. | É a negação da condição de nulidade apresentada em `IS NULL`. | [[07. Operadores e condições em consultas SQL#8. `NULL` precisa de `IS NULL`\|Artigo 07]] |
| **`LIKE`** | Predicado usado para procurar padrões em valores textuais. | Os curingas `%` e `_` recebem significado especial com `LIKE`. | [[07. Operadores e condições em consultas SQL#9. `LIKE`: procurar padrões em texto\|Artigo 07]] |
| **`%` em `LIKE`** | Curinga que representa nenhuma, uma ou várias posições em um padrão textual. | Difere de `_`, que representa exatamente uma posição. | [[07. Operadores e condições em consultas SQL#9. `LIKE`: procurar padrões em texto\|Artigo 07]] |
| **`_` em `LIKE`** | Curinga que representa exatamente um caractere em um padrão textual. | Não representa uma sequência de tamanho variável. | [[07. Operadores e condições em consultas SQL#9. `LIKE`: procurar padrões em texto\|Artigo 07]] |
| **`DESC`** | Palavra-chave usada em `ORDER BY` para solicitar ordenação decrescente. | Sem `DESC`, `ORDER BY` usa ordenação crescente por padrão. | [[07. Operadores e condições em consultas SQL#2. Comparação e ordenação são coisas diferentes\|Artigo 07]] |
| **Função agregada** | Função que resume um conjunto de valores em um resultado calculado. | Diferencia-se de uma expressão por linha, como `Preco * 2`. | [[08. Funções agregadas e cálculos em SQL#1. Visão geral das funções agregadas\|Artigo 08]] |
| **`AVG(coluna)`** | Função agregada que calcula a média dos valores não nulos de uma coluna. | `NULL` não é tratado como zero na média. | [[08. Funções agregadas e cálculos em SQL#2. `AVG`: calcular a média\|Artigo 08]] |
| **`COUNT(*)`** | Função agregada que conta linhas. | Não deve ser confundida com `COUNT(coluna)`, que ignora valores nulos da coluna. | [[08. Funções agregadas e cálculos em SQL#4. `COUNT(*)`: contar linhas\|Artigo 08]] |
| **`COUNT(coluna)`** | Função agregada que conta os valores não nulos de uma coluna. | Pode retornar menos que `COUNT(*)` quando existem valores `NULL`. | [[08. Funções agregadas e cálculos em SQL#5. `COUNT(coluna)`: contar valores não nulos\|Artigo 08]] |
| **`MAX(coluna)`** | Função agregada que retorna o maior valor não nulo de uma coluna. | Pode ser combinada com `WHERE` para restringir o conjunto analisado. | [[08. Funções agregadas e cálculos em SQL#7. `MAX`: encontrar o maior valor\|Artigo 08]] |
| **`MIN(coluna)`** | Função agregada que retorna o menor valor não nulo de uma coluna. | Funciona de forma análoga a `MAX`, procurando o extremo inferior. | [[08. Funções agregadas e cálculos em SQL#8. `MIN`: encontrar o menor valor\|Artigo 08]] |
| **`SUM(coluna)`** | Função agregada que soma os valores não nulos de uma coluna. | Pode ser aplicada ao conjunto filtrado por `WHERE`. | [[08. Funções agregadas e cálculos em SQL#9. `SUM`: somar valores\|Artigo 08]] |
| **Alias** | Nome temporário atribuído a uma coluna ou expressão no resultado de uma consulta. | Não cria nem renomeia uma coluna da tabela; apenas rotula o resultado daquela query. | [[08. Funções agregadas e cálculos em SQL#3. Alias: dar um nome mais claro ao resultado\|Artigo 08]] |
| **`GROUP BY`** | Cláusula que organiza linhas em grupos para que funções agregadas sejam calculadas separadamente para cada valor de agrupamento. | Sem `GROUP BY`, a agregação resume o conjunto inteiro; com ele, produz um resultado por grupo. | [[09. Cláusulas GROUP BY e HAVING#3. `GROUP BY`: agrupar linhas por um valor comum\|Artigo 09]] |
| **`HAVING`** | Cláusula que filtra grupos ou resultados agregados após o agrupamento. | Difere de `WHERE`, que restringe as linhas consideradas antes do agrupamento. | [[09. Cláusulas GROUP BY e HAVING#8. `HAVING`: filtrar resultados agregados\|Artigo 09]] |
| **Ordenação por posição** | Uso de um número em `ORDER BY` para indicar a posição da expressão na lista do `SELECT`. | `ORDER BY 2` ordena pela segunda expressão selecionada. | [[09. Cláusulas GROUP BY e HAVING#6. Ordenação pela posição da coluna no `SELECT`\|Artigo 09]] |

| **`JOIN`** | Operação usada para combinar linhas de tabelas relacionadas segundo uma condição. | Combina dados lado a lado; não deve ser confundido com `UNION`, que empilha linhas. | [[10. Cláusula JOIN, junções e UNION#3. Sintaxe de `JOIN`|Artigo 10]] |
| **`ON`** | Cláusula que expressa a condição usada para relacionar linhas em uma junção. | Define a correspondência entre tabelas; `WHERE` continua sendo usado para filtrar linhas do resultado. | [[10. Cláusula JOIN, junções e UNION#3. Sintaxe de `JOIN`|Artigo 10]] |
| **`INNER JOIN`** | Junção que retorna somente linhas com correspondência entre os lados relacionados. | A palavra `INNER` pode ser omitida nos exemplos estudados, ficando apenas `JOIN`. | [[10. Cláusula JOIN, junções e UNION#5. `INNER JOIN`: somente linhas com correspondência|Artigo 10]] |
| **`LEFT JOIN`** | Junção que preserva todas as linhas da tabela à esquerda e acrescenta correspondências da direita. | Quando não há correspondência, as colunas do lado direito aparecem como `NULL`. | [[10. Cláusula JOIN, junções e UNION#6. `LEFT JOIN`: preservar todas as linhas da esquerda|Artigo 10]] |
| **`RIGHT JOIN`** | Junção que preserva todas as linhas da tabela à direita e acrescenta correspondências da esquerda. | “Direita” se refere à posição da tabela no `FROM`, não à ordem das colunas no `SELECT`. | [[10. Cláusula JOIN, junções e UNION#7. `RIGHT JOIN`: preservar todas as linhas da direita|Artigo 10]] |
| **`FULL OUTER JOIN`** | Junção que preserva linhas correspondentes e não correspondentes dos dois lados. | Não é implementado diretamente no MySQL no cenário estudado. | [[10. Cláusula JOIN, junções e UNION#8. `FULL OUTER JOIN`: preservar os dois lados|Artigo 10]] |
| **Alias de tabela** | Nome temporário atribuído a uma tabela dentro de uma consulta. | Facilita qualificação de colunas e não renomeia a tabela no banco. | [[10. Cláusula JOIN, junções e UNION#10. Alias de tabela|Artigo 10]] |
| **`CROSS JOIN`** | Junção que produz todas as combinações possíveis entre as linhas de duas tabelas. | Com 2 linhas de um lado e 3 do outro, produz 6 combinações. | [[10. Cláusula JOIN, junções e UNION#11. `CROSS JOIN`: produto cartesiano|Artigo 10]] |
| **Produto cartesiano** | Resultado em que cada linha de um conjunto é combinada com cada linha do outro. | Pode ser intencional com `CROSS JOIN` ou surgir por falta de condição de relacionamento. | [[10. Cláusula JOIN, junções e UNION#11. `CROSS JOIN`: produto cartesiano|Artigo 10]] |
| **`UNION`** | Operador que empilha resultados compatíveis de diferentes `SELECT` e elimina linhas duplicadas. | Não combina colunas por chave; isso é papel de `JOIN`. | [[10. Cláusula JOIN, junções e UNION#14. `UNION`: unir resultados removendo duplicidades|Artigo 10]] |
| **`UNION ALL`** | Operador que empilha resultados compatíveis preservando todas as linhas, inclusive repetidas. | Difere de `UNION`, que remove duplicidades. | [[10. Cláusula JOIN, junções e UNION#15. `UNION ALL`: unir resultados preservando duplicidades|Artigo 10]] |
| **`DISTINCT`** | Palavra-chave que elimina linhas repetidas do resultado de um `SELECT`. | Atua dentro de um `SELECT`; `UNION` elimina duplicidades ao combinar resultados. | [[10. Cláusula JOIN, junções e UNION#18. `DISTINCT`: eliminar repetições dentro de um `SELECT`|Artigo 10]] |
