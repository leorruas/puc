# 02. Estruturas condicionais (if, else, switch, goto)

> **Contexto:** Estudo das estruturas de decisão e seleção simples, composta e múltipla em C#, Java, Python e JavaScript, acompanhado da análise histórica da instrução descontinuada `GOTO`, explicadas didaticamente através da Técnica de Feynman.

---

## 1. Seleção simples e composta (`if`, `else if`, `else`)

### A intuição (técnica de Feynman)
Imagine um segurança na porta de um clube:
1. Ele olha seu documento: **"Você tem 18 anos ou mais?"** (`if`). Se sim, você entra no clube VIP.
2. Se não tiver 18, ele olha para a fila do lado: **"Você está acompanhado de um responsável?"** (`else if`). Se sim, você entra na pista comum.
3. Se nenhuma das anteriores for verdadeira, a resposta padrão é **"Você não pode entrar"** (`else`).

O computador faz exatamente isso: testa uma pergunta lógica (booleana) por vez. Assim que encontra a primeira resposta **Verdadeira (`true`)**, ele executa aquela ação e ignora todas as outras perguntas abaixo.

### Comparativo de sintaxe

### C# / Java / JavaScript
```csharp
int nota = 85;

// Explicando o código:
// 1. Testa se nota é maior ou igual a 90
if (nota >= 90) {
    Console.WriteLine("Aprovado com distinção");
} 
// 2. Se a primeira for falsa, chega aqui e testa se nota é maior ou igual a 60
else if (nota >= 60) {
    Console.WriteLine("Aprovado");
} 
// 3. Se nenhuma das anteriores for verdadeira, executa o bloco alternativo
else {
    Console.WriteLine("Reprovado");
}
```

### Python
```python
nota = 85

# Em Python, 'else if' é abreviado para 'elif' e os blocos usam dois pontos ':' e indentação
if nota >= 90:
    print("Aprovado com distinção")
elif nota >= 60:
    print("Aprovado")
else:
    print("Reprovado")
```

## 2. Seleção múltipla (`switch` / `match`)

### A intuição (técnica de Feynman)
Imagina um menu de elevador ou um atendimento eletrônico ("Digite 1 para Vendas, 2 para Suporte, 3 para Financeiro"). 

Se você usar `if/else` para testar 10 opções, o computador terá que perguntar *"É 1? Não. É 2? Não. É 3?..."* uma por uma. O `switch` funciona como um **painel com botões diretos**: o computador pega o valor digitado e salta diretamente para o caso (*case*) correspondente.

### Comparativo de sintaxe com explicação linha por linha

### C#
```csharp
int dia = 2;

// O switch recebe a variável que será avaliada
switch (dia) {
    case 1: 
        Console.WriteLine("Domingo"); 
        break; // O 'break' obriga o computador a sair do switch após executar o caso
    case 2: 
        Console.WriteLine("Segunda"); 
        break;
    default: // O 'default' é executado se a variável não coincidir com nenhum case
        Console.WriteLine("Dia inválido"); 
        break;
}
```

### Java
```java
int dia = 2;

// Java moderno (14+) utiliza a sintaxe de flecha '->' que já inclui o break automático
switch (dia) {
    case 1 -> System.out.println("Domingo");
    case 2 -> System.out.println("Segunda");
    default -> System.out.println("Dia inválido");
}
```

### Python (3.10+)
```python
dia = 2

# Python 3.10 introduziu o 'match / case'. O caractere '_' atua como o default
match dia:
    case 1: print("Domingo")
    case 2: print("Segunda")
    case _: print("Dia inválido")
```

### JavaScript
```javascript
let dia = 2;

switch (dia) {
    case 1: console.log("Domingo"); break;
    case 2: console.log("Segunda"); break;
    default: console.log("Dia inválido"); break;
}
```

## 3. O caso histórico do `GOTO` (Salto incondicional descontinuado)

### A intuição (técnica de Feynman)
Imagine ler um livro onde, no meio da página 10, o texto diz: *"Agora vá para a página 250"*. Chegando lá, na terceira linha diz: *"Vá para a página 5"*. E na página 5 diz: *"Vá para a página 10"*. 

Você perde completamente a noção de onde começou e do que estava acontecendo! Isso era o `GOTO` nos anos 1960: o código virava um nó gigante (*Spaghetti Code*).

### Como funcionava no código e por que foi banido
O `GOTO` forçava a CPU a saltar aleatoriamente para qualquer marcação (rótulo) do arquivo. 

```csharp
// Exemplo histórico (CÓDIGO OBSOLETO - NÃO UTILIZAR)
int x = 0;

Inicio: // 1. Define um rótulo na memória chamado 'Inicio'
x++;
if (x < 5) 
    goto Inicio; // 2. Manda a execução saltar de volta para o rótulo 'Inicio'
```

* **Explicação do código:** Em vez de usar um laço limpo como `while (x < 5)`, o código criava uma marcação `Inicio:` e usava `goto Inicio;` para forçar o salto.
* **Por que foi descontinuado?** Em 1966, Böhm e Jacopini provaram matematicamente que esse tipo de salto pode ser **100% substituído por laços `while` e condicionais `if`**, tornando o programa legível, modular e sem riscos de saltos infinitos.

---

## 4. Armadilhas comuns

* **Fallthrough no `switch`:** Esquecer o `break` em C#/JS faz a execução "vazar" e executar os `case` seguintes sem testar.
* **Indentação em Python:** Se o bloco de código dentro do `if` não estiver alinhado com espaços, o programa não executa ou gera erro de compilação.
* **Uso de `GOTO`:** Tentar forçar o uso de `goto` em linguagens modernas que ainda possuem a palavra-chave (como C#) destrói a modularidade e a manutenibilidade do código.

## 5. Conexão com a modelagem de software: ramificações condicionais como o `«extend»` da UML

As estruturas de seleção e desvio condicional (`if`, `else`, `switch`) conectam-se diretamente à modelagem de requisitos:

* **Na Engenharia de Requisitos ([[07. Engenharia de Requisitos/08. Modelagem de requisitos com casos de uso e especificações textuais.md#3.4 Relacionamento de extensão («extend»)|Casos de Uso da UML]]):** O relacionamento `«extend»` modela ramificações opcionais ou regras condicionais de negócio. O caso de uso `Aplicar Cupom de Desconto` estende `Efetuar Compra` apenas se o usuário optar por fornecer um cupom promocional.
* **No Código:** Essa extensão é implementada através de um teste condicional (`if (cupom != null) { AplicarDesconto(cupom); }`). O fluxo base continua autônomo e opera mesmo sem a execução do bloco condicional.
