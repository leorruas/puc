# Manipulação e representação de datas e horários (DateTime, fusos e formatos)

> **Contexto:** Estudo da representação computacional de tempo, datas e intervalos cronológicos. Como os computadores guardam tempo sob a forma de inteiros puros (*Ticks* no .NET vs. *Epoch Unix* em outras linguagens), a anatomia do `DateTime` em C#, a API moderna de datas no Java 8+, o módulo `datetime` em Python e o objeto `Date` em JavaScript, explicados passo a passo pela Técnica de Feynman.

---

## Datas civis e instantes são representações diferentes de tempo

Humanos usam pelo menos dois tipos de conceito temporal que parecem semelhantes, mas não são equivalentes:

- uma **data/hora civil** descreve componentes de calendário, como “26/09/2026 às 14:30”, podendo ou não carregar informação de fuso;
- um **instante** identifica um ponto específico na linha do tempo, o que permite ordenar eventos e calcular durações de forma não ambígua.

Não existe uma única representação interna universal. Alguns tipos usam contadores relativos a uma época; outros armazenam campos de calendário. A analogia do “odômetro desde um marco zero” funciona bem para **timestamps e instantes**, mas não deve ser generalizada para toda API de datas.

| Linguagem / tipo | Modelo principal | Relação com época / fuso |
| :--- | :--- | :--- |
| C# `DateTime` | Data e hora com propriedade `Kind`; expõe `Ticks` de 100 ns desde `01/01/0001` | `Kind` pode ser `Utc`, `Local` ou `Unspecified`; não carrega um identificador completo de fuso |
| C# `DateTimeOffset` | Data/hora associada a um deslocamento UTC | Representa um instante de forma não ambígua pelo valor + offset |
| Java `LocalDateTime` | Campos de data e hora local | Não representa fuso nem instante por si só |
| Java `Instant` | Ponto na linha do tempo | Segundos desde `1970-01-01T00:00:00Z` + nanossegundos |
| Python `datetime` | Campos de calendário; pode ser *naive* ou *aware* | Pode ser convertido para timestamp POSIX; o objeto não deve ser reduzido conceitualmente ao timestamp |
| JavaScript `Date` | Instante representado numericamente | Milissegundos desde `1970-01-01T00:00:00Z`; métodos podem exibir componentes locais ou UTC |

> **Modelo mental:** primeiro pergunte se o domínio precisa representar uma **data civil**, um **horário local recorrente** ou um **instante real na linha do tempo**. Só depois escolha o tipo e a estratégia de armazenamento.

## `DateTime` e `DateTimeOffset` no .NET

No .NET, `DateTime` é uma `struct` e, portanto, um **tipo de valor**. Isso não significa que toda instância fique obrigatoriamente na *stack*: a localização física depende do contexto de uso e das otimizações do runtime.

Para o modelo público da API, os conceitos mais importantes são:

1. **`Ticks`:** número de intervalos de 100 nanossegundos transcorridos desde `01/01/0001 00:00:00` dentro do modelo de calendário usado pelo tipo.
2. **`Kind`:** informa se o valor deve ser interpretado como `Utc`, `Local` ou `Unspecified`.
3. **`DateTimeOffset`:** combina data/hora com um *offset* em relação a UTC e é frequentemente mais apropriado quando é necessário representar um instante sem ambiguidade.

A distinção é importante: um `DateTime` com `Kind.Unspecified` pode representar apenas uma data/hora civil, enquanto um `DateTimeOffset` identifica explicitamente sua relação com UTC.

## Comparação multilinguagem de datas e instantes

Abaixo está como instanciar, formatar e manipular tempo nas quatro principais linguagens:

### C# (.NET)
```csharp
using System;
using System.Globalization;

// 1. Criar data atual e data específica
DateTime agora = DateTime.Now;
DateTime dataNascimento = new DateTime(1995, 5, 20, 14, 30, 0);

// 2. Operações e cálculos de diferença (TimeSpan)
DateTime futuro = agora.AddDays(15);
TimeSpan diferenca = futuro - agora;
Console.WriteLine($"Dias de diferença: {diferenca.TotalDays}");

// 3. Formatação amigável (Interpolação / Custom Format)
string formatada = agora.ToString("dd/MM/yyyy HH:mm:ss", CultureInfo.InvariantCulture);
Console.WriteLine($"Ticks brutos em C#: {agora.Ticks}");
```

---

### Java (`java.time`)
```java
import java.time.LocalDateTime;
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.temporal.ChronoUnit;

// 1. Criar data atual e data específica
LocalDateTime agora = LocalDateTime.now();
LocalDate nascimento = LocalDate.of(1995, 5, 20);

// 2. Operações de tempo
LocalDateTime futuro = agora.plusDays(15);
long dias = ChronoUnit.DAYS.between(agora, futuro);

// 3. Formatação
DateTimeFormatter formato = DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm:ss");
System.out.println(agora.format(formato));
```

---

### Python (`datetime`)
```python
from datetime import datetime, timedelta

# Criar data atual e data específica
agora = datetime.now()
data_nascimento = datetime(1995, 5, 20, 14, 30, 0)

# Operações com timedelta
futuro = agora + timedelta(days=15)
diferenca = futuro - agora
print(f"Dias de diferença: {diferenca.days}")

# Formatação (strftime) e Timestamp Unix
print(agora.strftime("%d/%m/%Y %H:%M:%S"))
print(f"Timestamp Unix (segundos): {agora.timestamp()}")
```

---

### JavaScript (`Date`, `Intl` e APIs modernas)
```javascript
// 1. Criar data atual e data específica (Atenção: mês 0-indexado no construtor legado!)
const agora = new Date();
const dataNascimento = new Date(1995, 4, 20, 14, 30, 0); // Mês 4 = Maio!

// 2. Cálculos de tempo (Diferença em milissegundos desde Epoch Unix 1970)
const futuro = new Date(agora.getTime() + 15 * 24 * 60 * 60 * 1000);
const diferencaDias = (futuro - agora) / (1000 * 60 * 60 * 24);

// 3. Formatação moderna com Intl
const formatador = new Intl.DateTimeFormat('pt-BR', { dateStyle: 'short', timeStyle: 'medium' });
console.log(formatador.format(agora));
console.log(`Epoch Unix (milissegundos): ${agora.getTime()}`);
```

## Correspondência conceitual entre as APIs

| Linguagem | Tipos centrais | Modelo conceitual |
| :--- | :--- | :--- |
| **C#** | `DateTime`, `DateTimeOffset` | `DateTime` trabalha com data/hora e `Kind`; `DateTimeOffset` explicita offset e representa melhor um instante |
| **Java** | `LocalDate`, `LocalDateTime`, `Instant`, `ZonedDateTime` | Separa data/hora local, instante e data/hora associada a fuso |
| **Python** | `date`, `datetime`, `timezone`, `zoneinfo` | `datetime` pode ser *naive* ou *aware*; timestamps POSIX são uma conversão possível |
| **JavaScript** | `Date`, `Intl` e `Temporal` quando disponível | `Date` representa instante por milissegundos desde a época Unix; APIs de formatação e tipos modernos separam melhor calendário e fuso |

## Armadilhas de calendário, fuso e representação

1. **A pegadinha do mês zero em JavaScript:**
   - No construtor tradicional do JS `new Date(2026, 0, 1)`, o mês `0` é **Janeiro** e `11` é **Dezembro**. Passar `8` cria uma data em Setembro, e não Agosto!
2. **Tratar toda data como se fosse um instante UTC:**
   - Para eventos que representam um ponto real na linha do tempo, normalizar para um instante (frequentemente UTC) evita ambiguidades e facilita comparação.
   - Para conceitos civis como **data de aniversário**, “todo dia às 9h” ou uma data sem horário, converter indiscriminadamente para UTC pode distorcer o significado. Nesses casos, preserve o tipo civil e, quando necessário, o identificador do fuso usado pela regra de negócio.
3. **Imutabilidade varia entre APIs:**
   - `DateTime` no .NET e os principais tipos de `java.time` são imutáveis: operações retornam novos valores.
   - `datetime` em Python também é imutável.
   - `Date` do JavaScript, por outro lado, possui métodos mutáveis; por isso, é importante saber se a API altera o objeto ou retorna outro valor.
