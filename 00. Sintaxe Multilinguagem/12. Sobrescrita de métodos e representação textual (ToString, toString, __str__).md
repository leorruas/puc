# 12. Sobrescrita de métodos e representação textual (ToString, toString, \_\_str\_\_)

> **Contexto:** Todo objeto em linguagens orientadas a objetos herda de uma superclasse universal (`Object` em C# e Java, `object` em Python). Este guia compara a sintaxe e as convenções para **sobrescrever a representação textual de objetos** através do método `ToString()` (C#), `toString()` (Java e JavaScript) e `__str__` / `__repr__` (Python).

---

## 1. A intuição do ToString (Técnica de Feynman)

Imagine o **cartão de visitas ou a identidade de um objeto**:

* **O Comportamento Padrão de Fábrica:** Quando você cria um objeto na memória e tenta imprimi-lo diretamente (`Console.WriteLine(meuObjeto)` ou `print(meuObjeto)`), a superclasse ancestral universal só sabe informar o **nome do tipo e o endereço hexadecimal de memória** (ex.: `App.Dominio.ContaCorrente` ou `<ContaCorrente object at 0x7f9a>`).
* **A Necessidade do Cartão de Visitas Customizado:** Na prática, nenhum usuário ou desenvolvedor quer ler um ponteiro de memória ilegível. Queremos ver: `[Conta 123-X] Titular: Leo Ruas - Saldo: R$ 5.000,00`.
* **A Solução Polimórfica:** Sobrescrevemos o método padrão herdado da superclasse universal (`Object`) para que qualquer rotina de log, impressão em console ou concatenação de texto use automaticamente a nossa formatação customizada via **despacho dinâmico (*late binding*)**.

## 2. Matriz comparativa entre as 4 linguagens

| Recurso | C# | Java | Python | JavaScript / TypeScript |
| :--- | :--- | :--- | :--- | :--- |
| **Classe Raiz Universal** | `System.Object` | `java.lang.Object` | `object` | `Object.prototype` |
| **Nome do Método** | `ToString()` | `toString()` | `__str__(self)` / `__repr__(self)` | `toString()` |
| **Sintaxe de Sobrescrita** | Exige `public override string ToString()` | `@Override public String toString()` | `def __str__(self):` | `toString()` na classe |
| **Comportamento Padrão Sem Sobrescrita** | Retorna o *Namespace.NomeDaClasse* | Retorna *NomeDaClasse@Hashcode* | Retorna `<NomeDaClasse object at 0x...>` | Retorna `[object Object]` |
| **Acionamento Automático** | `Console.WriteLine(obj)`, interpolação `$"..."` | `System.out.println(obj)`, `"" + obj` | `print(obj)`, `str(obj)`, `f"{obj}"` | `console.log(String(obj))`, template literals |

## 3. Implementação comparada nas 4 linguagens

### C# (.NET)
Em C#, o método `ToString()` é declarado como `virtual` na classe raiz `System.Object`, exigindo obrigatoriamente a palavra-chave `override`:

```csharp
public class Produto 
{
    public string Nome { get; init; }
    public decimal Preco { get; init; }

    public Produto(string nome, decimal preco) 
    {
        Nome = nome;
        Preco = preco;
    }

    // Sobrescrita polimórfica obrigatória com override:
    public override string ToString() 
    {
        return $"{Nome} (R$ {Preco:F2})";
    }
}

// Uso:
Produto p = new Produto("Teclado Mecânico", 350.00m);
Console.WriteLine(p); // Imprime: Teclado Mecânico (R$ 350.00)
```

---

### Java
Em Java, todos os métodos de instância não-estáticos e não-finais são virtuais por padrão. Usa-se a anotação `@Override` para segurança em tempo de compilação:

```java
public class Produto {
    private String nome;
    private double preco;

    public Produto(String nome, double preco) {
        this.nome = nome;
        this.preco = preco;
    }

    @Override
    public String toString() {
        return String.format("%s (R$ %.2f)", nome, preco);
    }
}

// Uso:
Produto p = new Produto("Teclado Mecânico", 350.00);
System.out.println(p); // Imprime: Teclado Mecânico (R$ 350.00)
```

### Python
Em Python, métodos mágicos (*dunder methods*) como `__str__` (para exibição amigável ao usuário) e `__repr__` (para inspeção e depuração inequívoca) realizam esse papel:

```python
class Produto:
    def __init__(self, nome: str, preco: float):
        self.nome = nome
        self.preco = preco

    # Representação amigável para usuários finais (print / str):
    def __str__(self) -> str:
        return f"{self.nome} (R$ {self.preco:.2f})"

    # Representação técnica para desenvolvedores (logs / debug):
    def __repr__(self) -> str:
        return f"Produto(nome='{self.nome}', preco={self.preco})"

# Uso:
p = Produto("Teclado Mecânico", 350.00)
print(p) # Imprime: Teclado Mecânico (R$ 350.00)
```

---

### JavaScript / TypeScript
No ecossistema JS moderno, classes herdam de `Object.prototype`, onde `toString()` pode ser redefinido diretamente no corpo da classe:

```javascript
class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this.preco = preco;
  }

  toString() {
    return `${this.nome} (R$ ${this.preco.toFixed(2)})`;
  }
}

// Uso:
const p = new Produto("Teclado Mecânico", 350.00);
console.log(`${p}`); // Imprime: Teclado Mecânico (R$ 350.00)
```

## 4. Boas práticas universais para o ToString

1. **Nunca cause efeitos colaterais (*side effects*):** `ToString` deve ser uma operação pura de leitura e formatação; nunca deve alterar saldo, gravar arquivos ou disparar chamadas de rede.
2. **Nunca lance exceções:** O método é invocado automaticamente por ferramentas de depuração (debuggers de IDEs) e frameworks de log. Lançar `NullReferenceException` dentro de um `ToString()` pode travar a depuração da aplicação.
3. **Seja conciso e informativo:** Apresente os identificadores-chave que permitam distinguir a instância de forma rápida e clara.
