# Junção, união e eliminação de duplicidades em coleções

> **Contexto:** SQL oferece operações relacionais próprias, mas a ideia de combinar coleções por uma chave, concatenar sequências e remover duplicidades também aparece em linguagens de programação. As construções abaixo são analogias úteis; não são substitutos exatos do comportamento de um SGBD.

## Modelo mental

Há três operações diferentes:

| Intenção | SQL | Coleções em código |
| --- | --- | --- |
| combinar elementos relacionados por uma chave | `JOIN` | procurar correspondências entre coleções |
| empilhar elementos de duas sequências | `UNION ALL` | concatenar coleções |
| combinar eliminando repetidos | `UNION` / `DISTINCT` | união de conjuntos ou remoção de duplicidades |

A ideia é a mesma do [[03. Manipulação de Dados SQL/10. Cláusula JOIN, junções e UNION|artigo 10 de Manipulação de dados com SQL]]: **junção por chave** e **união de sequências** resolvem problemas diferentes.

## C#: LINQ

C# possui operadores LINQ que tornam a analogia bastante direta.

```csharp
var resultado =
    produtos.Join(
        fornecedores,
        produto => produto.FornecedorId,
        fornecedor => fornecedor.Id,
        (produto, fornecedor) => new
        {
            Produto = produto.Nome,
            Fornecedor = fornecedor.Nome
        }
    );
```

Leitura:

1. `produtos` é a coleção da esquerda;
2. `fornecedores` é a coleção relacionada;
3. cada produto fornece sua chave `FornecedorId`;
4. cada fornecedor fornece sua chave `Id`;
5. apenas correspondências são projetadas no resultado.

Para concatenar:

```csharp
var todos = categorias.Concat(produtos);
```

Para eliminar duplicidades:

```csharp
var distintos = nomes.Distinct();
```

## Java: streams e estruturas auxiliares

A API de streams não possui um `JOIN` relacional nativo equivalente ao de SQL. Uma estratégia comum é criar um índice por chave e depois consultar esse índice.

```java
Map<Integer, Fornecedor> porId =
    fornecedores.stream()
        .collect(Collectors.toMap(
            Fornecedor::getId,
            fornecedor -> fornecedor
        ));

var resultado =
    produtos.stream()
        .filter(p -> porId.containsKey(p.getFornecedorId()))
        .map(p -> new Object[] {
            p.getNome(),
            porId.get(p.getFornecedorId()).getNome()
        })
        .toList();
```

Para concatenar streams:

```java
Stream.concat(categorias.stream(), produtos.stream());
```

Para remover duplicidades:

```java
nomes.stream().distinct();
```

## Python: dicionários e compreensões

Python também pode usar um dicionário como índice por chave.

```python
fornecedores_por_id = {
    f["id"]: f
    for f in fornecedores
}

resultado = [
    {
        "produto": p["nome"],
        "fornecedor": fornecedores_por_id[p["fornecedor_id"]]["nome"]
    }
    for p in produtos
    if p["fornecedor_id"] in fornecedores_por_id
]
```

Para concatenar listas:

```python
todos = categorias + produtos
```

Para obter valores únicos quando a ordem não é o foco:

```python
distintos = set(nomes)
```

## JavaScript: arrays e mapas

Em JavaScript, um `Map` pode funcionar como índice por chave.

```javascript
const fornecedoresPorId = new Map(
  fornecedores.map(f => [f.id, f])
);

const resultado = produtos
  .filter(p => fornecedoresPorId.has(p.fornecedorId))
  .map(p => ({
    produto: p.nome,
    fornecedor: fornecedoresPorId.get(p.fornecedorId).nome
  }));
```

Para concatenar:

```javascript
const todos = [...categorias, ...produtos];
```

Para remover duplicidades:

```javascript
const distintos = [...new Set(nomes)];
```

## Comparação rápida

| Operação | C# | Java | Python | JavaScript |
| --- | --- | --- | --- | --- |
| combinar por chave | LINQ `Join` | índice com `Map` + stream | dicionário + compreensão | `Map` + `filter`/`map` |
| concatenar | `Concat` | `Stream.concat` | `+` | spread `...` |
| remover duplicidades | `Distinct` | `distinct` | `set` | `Set` |

> **Precisão conceitual:** essas operações em memória não possuem automaticamente as mesmas garantias, otimizações, semântica de `NULL` ou estratégia de execução de um `JOIN` em banco de dados. O paralelo serve para reconhecer o padrão de transformação de dados.

## Pontos que costumam gerar confusão

- **`JOIN` de SQL não é apenas um loop em duas listas.** O SGBD pode escolher estratégias de execução próprias e utilizar índices.
- **Concatenar não é juntar por chave.** `Concat`, `+` e spread se aproximam mais de `UNION ALL` do que de `JOIN`.
- **Eliminar duplicidades depende da regra de igualdade da linguagem.** `Distinct`, `set` e `Set` não reproduzem automaticamente todas as regras de comparação do SQL.
- **Java e JavaScript não possuem um operador relacional nativo idêntico a `JOIN` para arrays/streams.** É comum construir índices por chave ou usar bibliotecas.
