# Desenvolvimento web back-end

## Visão geral

A disciplina estuda como aplicações Web são estruturadas e executadas do ponto de vista do servidor. O percurso começou pelos fundamentos de arquitetura de software e cliente-servidor, avançou por estilos arquiteturais e estratégias de renderização e chegou à implementação com PHP, frameworks Web, MVC, Razor, Entity Framework Core, validação e persistência no ASP.NET Core MVC.

O conteúdo se conecta diretamente a [[01. Programacao Modular/00. Programação modular - Resumo|Programação modular]], especialmente em modularidade, acoplamento e responsabilidades; a [[02. Modelagem de Dados/00. Modelagem de Dados - Resumo|Modelagem de dados]], pela passagem entre classes, entidades e estruturas relacionais; e a [[03. Manipulacao de Dados SQL/00. Manipulacao de Dados SQL - Resumo|Manipulação de dados com SQL]], porque frameworks e ORMs não eliminam o banco relacional nem as operações que acontecem sobre ele.

## Pontos centrais até agora

Arquitetura de software descreve decisões estruturais sobre partes do sistema, responsabilidades, relacionamentos e princípios de evolução. Ela não é sinônimo de framework, infraestrutura ou diagrama. O **domínio** representa o problema e suas regras, enquanto a arquitetura organiza a solução para atender esse domínio.

Em aplicações Web, a arquitetura cliente-servidor organiza a comunicação entre componentes: o cliente inicia uma requisição e o servidor produz uma resposta. HTTP fornece o protocolo dessa comunicação, enquanto decisões sobre distribuição, camadas, implantação e responsabilidades determinam como o sistema é organizado. *Layers* representam separações lógicas; *tiers*, separações físicas ou de implantação.

Estilos arquiteturais não são categorias mutuamente exclusivas. Uma aplicação pode ser cliente-servidor, possuir um back-end monolítico, organizar esse monólito em camadas e ainda utilizar pipelines ou mecanismos de extensão. Por isso, arquitetura envolve **trade-offs**: escalabilidade, desempenho, segurança, manutenibilidade, disponibilidade e simplicidade podem exigir decisões diferentes conforme o contexto.

MPA e SPA descrevem principalmente como a navegação e atualização da interface são organizadas. CSR, SSR e SSG respondem a outra questão: onde ou quando a interface é renderizada. AJAX e Fetch permitem comunicação assíncrona com o servidor, e APIs podem separar a interface do back-end sem eliminar a lógica cliente-servidor.

PHP funciona como caso concreto para compreender execução server-side: o servidor Web recebe a requisição, encaminha o processamento para a aplicação, que pode interpretar parâmetros, executar regras, acessar o banco e produzir uma resposta. A partir desse fluxo, a disciplina compara runtimes, linguagens, tipagem, compilação/interpretação e diferentes ecossistemas de desenvolvimento back-end.

Frameworks Web fornecem infraestrutura reutilizável para problemas recorrentes, como roteamento, validação, autenticação, geração de respostas e persistência. No ASP.NET Core MVC, o estudo avançou da separação entre Model, View e Controller para Razor, Entity Framework Core, `DbContext`, injeção de dependência, model binding, validação, migrations e operações de persistência. O ORM cria uma ponte entre objetos e banco relacional, mas não substitui o modelo relacional nem torna SQL conceitualmente irrelevante.
