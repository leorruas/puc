## Pontos centrais até agora

SQL é uma linguagem, não um banco de dados nem um SGBD. Ela permite expressar operações sobre estruturas relacionais, enquanto o SGBD decide como executar essas operações e administrar os dados.

A linguagem é declarativa porque descreve principalmente **o que** se deseja obter ou realizar, deixando para o SGBD a escolha de **como** executar a operação. Também é de alto nível porque abstrai detalhes físicos de armazenamento e processamento.

DDL, DML, DQL e DCL organizam as instruções conforme sua finalidade. `CREATE TABLE` pertence à DDL porque define a estrutura de uma tabela; comandos como `INSERT`, `UPDATE` e `DELETE` atuam sobre seus dados, enquanto `SELECT` realiza consultas e pode aparecer classificado como DQL ou DML conforme a referência.

A estrutura relacional conecta diretamente esta disciplina a Modelagem de dados. Entidades tornam-se tabelas, atributos tornam-se colunas, identificadores tornam-se chaves primárias e relacionamentos serão implementados por chaves estrangeiras e restrições.

No modelo relacional, **domínio** significa o conjunto de valores válidos para um atributo. Esse sentido é diferente de **domínio da aplicação** em [[05. Desenvolvimento Web Back-End/01. Arquitetura de software e cliente-servidor#O que é domínio|Desenvolvimento Web Back-End]], onde domínio representa a área de problema, seus conceitos e regras.

MySQL, PostgreSQL e SQL Server implementam SQL, mas possuem diferenças de sintaxe, tipos e recursos. Por isso, é importante distinguir conceitos transferíveis da linguagem de extensões ou comportamentos específicos de cada SGBD.
