# O que é SQL

SQL é a sigla para **Structured Query Language**, ou Linguagem de Consulta Estruturada. É uma linguagem criada para trabalhar com dados armazenados em bancos de dados relacionais e é adotada, com algumas variações, pelos principais Sistemas Gerenciadores de Bancos de Dados relacionais, os SGBDs.

Por meio de SQL, é possível consultar informações, inserir novos registros, modificar ou excluir dados existentes, criar e alterar estruturas do banco de dados e controlar quais usuários possuem acesso a determinados recursos. Por isso, conhecer SQL é uma habilidade importante para profissionais que trabalham com desenvolvimento de software, administração de bancos de dados, análise de sistemas, engenharia de software e também com dados, como analistas, engenheiros e cientistas de dados.

SQL trabalha principalmente com o nível lógico dos dados. Em geral, quem escreve uma instrução SQL informa ao SGBD o resultado que deseja obter ou a operação que deseja realizar, sem precisar descrever passo a passo como os dados devem ser encontrados ou manipulados fisicamente.

## Uma linguagem declarativa e de alto nível

SQL é considerada uma **linguagem declarativa**. Isso significa que uma instrução normalmente descreve **o que se deseja obter ou realizar**, enquanto o SGBD decide **como executar essa operação**.

Considere uma tabela chamada `Cliente`. Se quisermos encontrar todos os clientes que vivem em Belo Horizonte, podemos escrever:

```sql
SELECT *
FROM Cliente
WHERE cidade = 'Belo Horizonte';
```

A instrução estabelece o resultado desejado: recuperar os registros da tabela `Cliente` cuja cidade seja Belo Horizonte. Entretanto, ela não determina uma sequência detalhada de operações como abrir determinado arquivo, percorrer registros em uma ordem específica ou comparar cada valor manualmente.

Quem determina a estratégia concreta de execução é o próprio SGBD. Ele pode, por exemplo, percorrer toda a tabela ou utilizar um índice existente. Essa estratégia é chamada de **plano de execução**.

É nesse sentido que SQL também pode ser considerada uma linguagem de **alto nível**: ela oferece uma abstração que permite trabalhar com tabelas, colunas, relações e conjuntos de dados sem controlar diretamente detalhes de armazenamento, endereços de memória ou algoritmos internos usados para recuperar esses dados.

O termo **Structured** em *Structured Query Language* não significa que SQL seja de alto nível. O nome tem origem histórica na linguagem **SEQUEL, Structured English Query Language**, desenvolvida na IBM na década de 1970.

## Principais grupos de instruções SQL

As instruções SQL costumam ser classificadas de acordo com aquilo que realizam. Uma divisão didática bastante comum utiliza DDL, DML e DCL. Algumas referências também separam as consultas em uma categoria chamada DQL.

### DDL: Data Definition Language

A **Data Definition Language**, ou Linguagem de Definição de Dados, reúne comandos usados para definir e modificar a **estrutura do banco de dados**. Ela permite trabalhar com objetos como tabelas, colunas, visões e índices.

Os principais comandos são:

- `CREATE`: cria um objeto;
- `ALTER`: modifica a estrutura de um objeto existente;
- `DROP`: remove um objeto.

Por exemplo:

```sql
CREATE TABLE Cliente (
    id INTEGER,
    nome VARCHAR(100)
);
```

Aqui não estamos inserindo clientes. Estamos definindo a estrutura que permitirá armazená-los.

### DML: Data Manipulation Language

A **Data Manipulation Language**, ou Linguagem de Manipulação de Dados, reúne instruções usadas para trabalhar com os dados armazenados nas estruturas do banco.

Entre os comandos mais conhecidos estão:

- `INSERT`: insere dados;
- `UPDATE`: altera dados existentes;
- `DELETE`: remove dados;
- `SELECT`: consulta dados, dependendo da classificação adotada.

Por exemplo:

```sql
INSERT INTO Cliente (id, nome)
VALUES (1, 'Ana');
```

Nesse caso, a tabela já existe e estamos manipulando seu conteúdo.

Existe uma diferença de classificação entre materiais didáticos. Algumas referências consideram `SELECT` parte da DML porque ele trabalha com os dados. Outras criam uma categoria separada chamada **DQL, Data Query Language**, especificamente para operações de consulta. Assim, é possível encontrar `SELECT` classificado tanto como DML quanto como DQL.

### DCL: Data Control Language

A **Data Control Language**, ou Linguagem de Controle de Dados, está relacionada ao controle de acesso e às permissões sobre os objetos de um banco de dados.

Dois comandos importantes são:

- `GRANT`: concede privilégios;
- `REVOKE`: remove privilégios.

Esses comandos permitem definir, por exemplo, se determinado usuário pode consultar uma tabela, modificar seus registros ou realizar outras operações.

## A origem do SQL

SQL surgiu durante a década de 1970 a partir das pesquisas da IBM sobre bancos de dados relacionais. Donald Chamberlin e Raymond Boyce desenvolveram uma linguagem chamada inicialmente **SEQUEL, Structured English Query Language**, baseada no modelo relacional proposto por Edgar F. Codd.

A intenção era permitir que usuários trabalhassem com o modelo relacional utilizando uma linguagem mais acessível do que as notações matemáticas usadas nas primeiras pesquisas sobre bancos de dados. Posteriormente, o nome passou de SEQUEL para SQL. A linguagem foi utilizada no projeto **System R**, da IBM, um dos primeiros sistemas experimentais a implementar o modelo relacional.

Durante os anos seguintes, diferentes empresas passaram a implementar SQL em seus próprios SGBDs. Em 1986 ocorreu sua primeira padronização formal pelo ANSI, seguida pela padronização internacional pela ISO. Desde então, o padrão SQL recebe revisões periódicas.

## Padrão SQL, extensões e dialetos

Embora exista um padrão para SQL, os fabricantes de SGBDs podem adicionar recursos próprios à linguagem. Essas diferenças costumam ser chamadas de **extensões** ou **dialetos SQL**.

Um banco como PostgreSQL, MySQL, Oracle Database ou Microsoft SQL Server implementa uma parte ampla da linguagem SQL padronizada, mas também pode oferecer comandos, funções, tipos de dados ou formas de escrever determinadas operações que não existem da mesma maneira nos demais sistemas.

Uma extensão, portanto, é uma funcionalidade acrescentada por determinado fabricante ou projeto além do conjunto padronizado da linguagem. Ela pode facilitar certas tarefas ou oferecer recursos específicos daquele SGBD, mas também pode reduzir a portabilidade do código para outros bancos.

Isso significa que consultas simples provavelmente funcionarão de maneira semelhante em vários SGBDs, enquanto funcionalidades mais específicas podem depender do sistema utilizado. Neste microfundamento, o foco será principalmente o **SQL padronizado pelo ANSI/ISO**, de forma que os conceitos estudados possam ser transferidos para diferentes bancos de dados relacionais.

## SQL e o modelo relacional

SQL está diretamente ligado ao conteúdo estudado em [[02. Modelagem de Dados/00. Modelagem de Dados - Resumo|Modelagem de Dados]]. Na modelagem, definimos entidades, atributos, relacionamentos, chaves e restrições e depois transformamos esse modelo em estruturas relacionais. SQL fornece a linguagem usada para interagir com essas estruturas.

Existe, portanto, uma continuidade entre as duas disciplinas:

**modelo conceitual → modelo relacional → banco de dados → operações SQL**

A modelagem responde principalmente a perguntas como **"como os dados devem ser organizados?"**. SQL acrescenta outra pergunta: **"como podemos definir, consultar e modificar esses dados?"**.

Essa distinção será importante ao longo da disciplina, porque aprender SQL envolve menos decorar comandos isolados e mais compreender como cada operação atua sobre tabelas, relações e conjuntos de dados.

## Pontos que costumam gerar confusão

- **SQL é declarativa porque diz o que se deseja, não porque se chama Structured.** O SGBD decide como executar a instrução.
- **Alto nível significa abstração.** O usuário não precisa controlar diretamente a forma física de armazenamento ou o algoritmo usado para acessar cada registro.
- **DDL altera a estrutura; DML altera ou manipula os dados.** `CREATE TABLE` define uma tabela; `INSERT` adiciona registros nela.
- **DQL não é uma classificação universal.** Alguns materiais separam `SELECT` em DQL; outros o consideram parte de DML.
- **Extensões são recursos específicos de um SGBD.** O SQL padrão fornece uma base comum, enquanto PostgreSQL, MySQL, Oracle e SQL Server podem acrescentar sintaxes e funcionalidades próprias.
